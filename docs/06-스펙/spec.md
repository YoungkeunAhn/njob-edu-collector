# Feature Specification: N잡러 교육 매칭 (앱인토스 미니앱)

**Created**: 2026-10-11
**Status**: Implemented (MVP 코드 완료 2026-10-12, 배포 전 — [배포 런북](../07-운영/배포-런북.md), 결정은 [plan.md](plan.md) 「결정 기록」)
**Input**: 지역과 분야를 고르면 들을 수 있는 AI 교육·세미나 목록을 보여준다. 목록과 상세 화면에 배너 광고를 단다. 강의 데이터는 매일 정해진 시간에 수집한다.

> 형식: GitHub Spec Kit의 `spec.md` 템플릿을 따른다. 이 문서는 **무엇을, 왜** 만드는지만 다룬다. **어떻게** 만드는지는 [plan.md](plan.md)에 있다.

## 서비스 원칙

- **정보 제공 서비스다.** 교육 콘텐츠를 팔지 않는다. 강좌 정보를 모아서 보여주고, 원문 링크로 연결한다.
- **판단은 사용자가 한다.** 자격 판정, 추천, 신청 대행은 하지 않는다.
- **비용은 막지 않는다.** 무료, 내일배움카드(자부담), 유료 강좌를 모두 보여주고 가격을 표시한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 지역·분야로 강좌 찾기 (Priority: P1)

사용자가 지역(시도 → 시군구), 분야(대분류 → 소분류), 유형(원데이 클래스 / 교육훈련)을 고른다. **"강의 찾기"** 버튼을 누르면 조건에 맞는 강좌 목록이 바로 뜬다. 목록 중간에 배너 광고가 끼어 있다.

**Why this priority**: 서비스의 핵심 기능이다. 유일한 수익원인 배너 광고도 이 화면에 붙는다.

**Independent Test**: DB에 강좌 몇 건을 넣고 앱에서 조건을 골라 버튼을 누른다. 조건에 맞는 강좌만 목록에 나오고, 목록 중간에 배너가 보이면 성공이다.

**Acceptance Scenarios**:

1. **Given** 경기도·AI 영상·원데이를 고른 상태, **When** "강의 찾기"를 누르면, **Then** 경기도 오프라인 원데이 AI 영상 강좌와 온라인(전국) 원데이 AI 영상 강좌가 접수 마감일 순으로 나온다.
2. **Given** 목록, **When** 스크롤하면, **Then** 5번째 카드 뒤(5개 미만이면 마지막 카드 뒤)에 배너 광고 1개가 보인다. 배너는 강좌 카드와 구분되게 "광고" 표시가 붙는다.
3. **Given** 조건에 맞는 강좌가 없을 때, **When** 버튼을 누르면, **Then** "조건에 맞는 강좌가 없어요" 화면과 조건 바꾸기 버튼이 나온다.
4. **Given** 배너 로드에 실패했을 때, **When** 목록을 보면, **Then** 배너 자리는 빈칸 없이 사라지고 목록은 정상으로 보인다.
5. **Given** 목록, **When** 강좌 카드를 보면, **Then** 제목, 기관, 지역(또는 온라인), 기간, 가격(무료 / 내배카 자부담액 / 유료 금액), 유형, 접수 마감일이 보인다.
6. **Given** 목록, **When** 정렬 칩(마감순·가격순·최신순)을 고르면, **Then** 그 순서로 다시 나온다. 기본은 마감순이다. (2026-10-14 추가, [plan.md](plan.md) D16)
7. **Given** 목록, **When** 검색창에 제목 일부를 넣고 찾으면, **Then** 지금 고른 조건 안에서 제목이 맞는 강좌만 나온다(띄어쓰기·기호 무시). 약어는 영어·한글 이름 어느 쪽으로 써도 찾고("지피티" = "GPT"), 초성("ㅈㅍㅌ")과 한/영 전환을 잊고 친 검색어("wlvlxl")도 찾는다. (2026-10-14 추가, 2026-10-15 보강)
8. **Given** 목록을 스크롤하거나 "더 보기"로 펼친 상태, **When** 상세를 보고 뒤로 가면, **Then** 같은 카드와 같은 위치가 그대로 보인다. (2026-10-14 추가)

### User Story 2 - 강좌 상세 보고 원문으로 이동 (Priority: P1)

사용자가 목록에서 강좌를 누르면 앱 안에서 상세 정보를 본다. 신청하려면 보조 버튼 **"원문 보기"**를 눌러 원 사이트로 이동한다.

**Why this priority**: 서비스 원칙(링크 연결, 판단은 사용자)을 구현하는 화면이다. 앱인토스 정책상 상세 정보를 앱 안에서 보여줘야 한다.

**Independent Test**: 목록에서 강좌 1건을 눌러 상세 화면을 보고, "원문 보기"를 눌러 원 사이트가 열리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 목록, **When** 강좌를 누르면, **Then** 상세 화면에 목록 정보와 함께 접수기간, 교육기간, 대상(원문 그대로), 장소, 출처가 나온다.
2. **Given** 상세 화면, **When** "원문 보기"를 누르면, **Then** 앱인토스 SDK `openURL`로 원문 페이지가 열린다.
3. **Given** 상세 화면, **When** 화면을 보면, **Then** "신청 조건과 상세 내용은 원문에서 확인하세요" 안내가 있다.
4. **Given** 원천이 정원을 주는 강좌, **When** 상세를 보면, **Then** "인원" 줄에 정원이 나온다. 고용24 강좌는 신청 인원과 커리큘럼(교과목·단원·시간)도 나온다. 고용24 원문을 못 읽어도 나머지 상세는 그대로 보인다. (2026-10-14 추가)

### User Story 3 - 매일 강좌 데이터 갱신 (Priority: P1)

시스템이 매일 새벽(KST)에 1차 소스 16개에서 **모집 중인** 강좌를 수집한다. 분기·학기 단위로 바뀌는 소스는 주 1회 수집한다. 새 강좌는 추가하고, 바뀐 강좌는 갱신하고, 마감된 강좌는 지운다.

**Why this priority**: 데이터가 없으면 서비스가 성립하지 않는다.

**Independent Test**: 수집을 수동으로 1회 실행한 뒤 소스별 수집 건수가 기록되고, 앱 목록에 새 강좌가 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 소스 하나가 오류를 낼 때, **When** 수집이 돌면, **Then** 그 소스만 실패로 기록되고 나머지 소스는 정상 수집된다.
2. **Given** 접수 마감일이 지난 강좌, **When** 후처리가 돌면, **Then** DB에서 지워진다. 그전에도 조회 API는 마감일이 지난 강좌를 내보내지 않는다.
3. **Given** 원천에서 사라진 강좌(조기 마감·취소), **When** 그 소스 수집이 성공하면, **Then** DB에서 지워진다. 수집이 실패했거나 건수가 직전 대비 50% 미만이면 지우지 않고 알린다.
4. **Given** 수집된 강좌, **When** 분류가 끝나면, **Then** 카테고리(대·소분류), 유형(원데이 / 교육훈련), 시군구 코드가 붙는다. 카테고리 키워드에 안 걸린 강좌는 저장하되 노출하지 않는다.

### Edge Cases

- 배너 로드에 실패하면 → 배너 자리를 숨기고 목록은 그대로 보여준다(User Story 1 시나리오 4).
- 온라인 강좌는 지역이 없다. → 모든 지역 결과에 "온라인(전국)"으로 함께 보여준다.
- 거주지 제한 강좌(예: "경기도민만")는 지역 필터와 별개다. → 대상 원문을 그대로 보여주고 판단은 사용자에게 맡긴다.
- 날짜가 없는 강좌 → 유형은 제목 키워드로 판정한다(`원데이`·`특강`·`세미나`·`1일`이면 원데이). 마감일이 없으므로 원천에서 사라질 때 지운다.
- 같은 강좌가 여러 소스에 있다 → 제목 정규화 + 기관 + 시작일이 같으면 하나만 보여준다(공식 API 소스 우선).
- 가격을 모르는 강좌 → "가격: 원문 확인"으로 표시한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 앱은 지역(시도·시군구, 최대 3곳까지 함께 선택), 분야(대분류 6·소분류 18), 유형(원데이 클래스·교육훈련)으로 필터를 고를 수 있어야 한다.
> **보류(2026-10-13)**: 사용자 결정 "일단은 배너 광고 빼줘"로 첫 출시에는 광고를 넣지 않는다. 다시 넣을 때 아래 규칙을 따른다(코드는 git 이력의 `app/src/Banner.tsx`).
- **FR-002**: 앱은 화면마다 앱인토스 배너를 **1개만** 보여줘야 한다. 목록은 5번째 카드 뒤(5개 미만이면 마지막 카드 뒤), 상세는 본문 아래다. 앱인토스 정책이 같은 화면에 같은 포맷 광고 2개 이상을 금지한다.
- **FR-003**: 배너는 "원문 보기" 버튼과 붙여 두지 않아야 한다(잘못 누르기 방지, 클릭 유도 금지 정책).
- **FR-004**: 인트로·로딩 화면과 팝업에는 광고를 두지 않아야 한다. 배너는 스크롤되는 화면에만 둔다(앱인토스 정책).
- **FR-005**: 목록과 상세에는 기간(접수·교육)과 가격(유형 + 금액)을 표시해야 한다. 상세에는 아는 경우 정원·신청 인원과 커리큘럼(고용24)도 표시한다(2026-10-14).
- **FR-006**: 원문 링크는 상세 화면의 보조 버튼으로 두고 SDK `openURL`로 열어야 한다.
- **FR-007**: 시스템은 [plan.md](plan.md)의 소스별 스케줄(매일 또는 주 1회)대로 1차 소스 16개의 **모집 중인 강좌만** 수집해야 한다. 소스 하나가 실패해도 나머지는 계속 수집해야 한다.
- **FR-008**: 시스템은 수집한 강좌를 `(source, source_id)` 기준으로 upsert해야 한다.
- **FR-009**: 시스템은 접수 마감일(없으면 교육 시작일)이 지난 강좌와, 수집이 성공한 소스에서 사라진 강좌를 지워야 한다. 마감된 강좌는 보관하지 않는다.
- **FR-010**: 시스템은 강좌마다 카테고리, 유형, 시군구 코드를 붙여야 한다. 분류는 키워드 룰로만 하고, 키워드에 안 걸린 강좌는 노출하지 않는다.
- **FR-011**: 시스템은 소스별 수집 결과(성공 여부, 건수, 오류)를 기록하고, 전날보다 50% 넘게 줄거나 실패하면 **텔레그램**으로 알려야 한다.
- **FR-012**: 앱은 조회 API(Worker)만 호출하고, DB에 직접 접근하지 않아야 한다.
- **FR-013**: 조회 API는 정해진 조회만 받고, IP당 요청 수를 제한해야 한다.
- **FR-014**: 시스템은 강사명, 담당자 연락처, 설명문 전문, 이미지 파일을 저장하지 않아야 한다(개인정보·저작권). 이미지는 원천 **공식 API**가 주는 https 링크만 저장해 표시하고(서울 공공서비스예약 `IMGURL`, K-MOOC `course_image`), 크롤링한 페이지의 이미지는 쓰지 않는다. 링크가 없으면 앱이 분야별 일러스트를 보여주고, 이 일러스트는 생성형 AI로 만들었으므로 "AI 생성 이미지"로 표기한다. (2026-10-13 변경) 고용24 상세의 신청 인원·커리큘럼은 사용자가 상세를 열 때 받아 보여주기만 하고 저장하지 않는다(응답 캐시 6시간). 교과목·단원 이름과 시간만 쓰고 세부내용·강사는 쓰지 않는다. (2026-10-14, [plan.md](plan.md) D15)

### Key Entities

- **Course(강좌)**: 수집된 강좌 1건. 제목, 기관, 유형(원데이/교육훈련), 카테고리, 지역(시도·시군구), 온·오프라인, 가격(유형·금액), 접수기간, 교육기간, 대상(원문), 원문 URL, 이미지 링크(공식 API 제공분만). 원천 레코드 원본(raw)은 FR-014 위반 소지가 있어 저장하지 않는다. 모집 중인 강좌만 존재한다.
- **Source(소스)**: 수집 원천 1개. 코드, 이름, 수집 방식(API/HTML/헤드리스), 라이선스, robots·약관 확인 결과, 출처 표기 문구, 사용 여부.
- **CollectRun(수집 실행 기록)**: 소스별 1회 수집 결과. 시작·종료 시각, 성공 여부, 건수, 오류 메시지.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 앱을 연 뒤 3번 이내의 선택으로 목록에 도달한다(광고 대기 없음).
- **SC-002**: 목록에 나오는 강좌 중 접수가 이미 끝난 강좌는 1% 미만이다.
- **SC-003**: 매일 수집에서 1차 소스 16개 중 14개 이상이 성공한다.
- **SC-004**: 목록 조회 응답은 캐시 적중 시 300ms, 미적중 시 1초 이내다(서울 기준).
- **SC-005**: 월 인프라 비용은 출시 초기 $5 이내다.
- **SC-006**: 무작위 50건 표본에서 카테고리 분류 정확도가 90% 이상이다(월 1회 사람 점검).
