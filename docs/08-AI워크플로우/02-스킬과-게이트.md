# 스킬과 게이트

스킬은 이 레포의 `.claude/skills/` 에만 있어서 **이 프로젝트에서만** 보인다. 모두 `disable-model-invocation: true` — **사용자가 직접 쳐야만 돈다.**

## 스킬

| 호출 | 하는 일 | 멈추는 곳 |
|---|---|---|
| **`/flow <변경사항>`** (기본) | 1~4단계를 이어서. 아래 단계 스킬의 절차를 순서대로 따르되 단계 사이에 멈추지 않는다 | 앞쪽 질문 1회(있을 때만) · **실기기 확인** |
| **`/flow-submit #N`** | 5단계. 부르는 것 = 실기기 확인 통과 | 검수요청 hook 확인 |
| **`/flow-close #N`** | 6단계. 부르는 것 = 출시(또는 Cron 결과) 확인. 라이브 번들·`collect_run` 으로 끝났는지 본 뒤 docs 이관 → 백로그 폴더 삭제 → 이슈 닫기 | 끝 |
| `/flow-ticket <변경사항>` | 1단계만 | 이슈 등록 |
| `/flow-plan #N` | 2단계만 (착수: `stage:ticket`) | G0 질문 |
| `/flow-impl #N` | 3단계만 (착수: `plan-approved`) | 마지막 노드 커밋 |
| `/flow-ship #N` | 4단계만 (착수: `stage:built`) | 토스 테스트 푸시 |

- 정본: `.claude/skills/flow*/SKILL.md`. 절차를 바꿀 땐 그 파일을 고치고 이 표를 맞춘다.
- `/flow` 의 작은 변경(노드 1개 · Q 0개 · DB 없음) 축약: 계획 문서는 사실·노드·T-id 만, 계획 문서는 N1 커밋에 같이, W 변이 생략, `/code-review low`, 이슈 라벨·댓글은 테스트 푸시 뒤 한 번에.

## 단계별 산출물 위치

| 무엇 | 어디 |
|---|---|
| 무엇을 할지(요구·완료 기준) | GitHub 이슈 본문 — [티켓 양식](01-티켓-양식.md) |
| 어떻게 할지(실행 그래프) | `backlogs/NNN-이슈<N>-<요지>/00-START-HERE.md` |
| 진행 상황 | 이슈 라벨 + 이슈 댓글 |
| 배포 기록 | 그래프 문서 상태 줄 + `backlogs/00-START-HERE.md` 상태 열 → 마감 때 이슈 댓글 |
| 끝난 뒤 남는 것 | 결정 = `plan.md` 「결정 기록」 D 번호 · 운영 주의 = 런북·소스 문서 · 방법론 = 이 문서 회고 · 나머지 = 닫힌 이슈 |

## 게이트 (hook)

| 동작 | 왜 |
|---|---|
| `mcp__apps-in-toss-console__bundle_submit_review` · `review_submit` | 외부(토스 검수)로 나가고 되돌릴 수 없다. bypass 모드에서도 확인을 받는다 |

- 설정: `.claude/settings.json` → `.claude/hooks/gate.mjs` (PreToolUse, `permissionDecision: "ask"`). 게이트를 늘리려면 `settings.json` 의 `matcher` 에 도구 이름을 더한다.
- `git push`·번들 업로드·테스트 푸시는 게이트가 없다 — 혼자 쓰는 레포이고, 테스트 번들은 사용자에게 안 나간다.
- 운영 Worker·DB 배포는 hook 이 아니라 `/flow` 앞쪽 질문에서 한 번 승인받는다.

## 사람이 하는 일
- `/flow` 앞쪽 질문에 답(있을 때만)
- DB 마이그레이션 적용(SQL Editor) — 마이그레이션이 있을 때만
- 토스앱에서 실기기 확인 → `/flow-submit #N`
- 검수요청 hook 확인
- 검수 통과 시 콘솔 "출시하기" → `/flow-close #N`

## 실행 그래프 회고 (001 MVP · 002 사용자 피드백, 2026-10-11~15)
그래프 문서는 `/flow-close` 로 지웠다. 원문은 git: `git show a263644:backlogs/001-MVP-실행그래프.md` · `…:backlogs/002-사용자피드백-6건-실행그래프.md`.
- 수집기에서 데이터를 지우는 경로(정리)는 "값이 있는데 못 읽으면 throw, 비어 있을 때만 null"과 "총건수로 완전 수집 검증"을 공통 함수(`collectPages`·`kdate`·`kurl`)로 강제해야 수렴했다. 어댑터마다 막으면 교차검증이 끝없이 새 입력을 찾는다(001 N6 7라운드). 총건수가 없는 소스는 정리를 끈다(`prune=false`).
- 화면 노드는 브라우저 테스트가 테스트 코드가 못 본 실제 버그를 잡는다(배너 effect 의존성, 빈 `<li>`). 교차검증은 상태 수명(마운트·history) 문제를 거의 매 라운드 찾았다 — 계획 때 "같은 컴포넌트가 다른 조건·다른 id 로 재사용되는가"를 op × 상태 표의 행으로 넣는다.
- 메모리가 적은 PC 에서는 백그라운드 명령이 강제 종료된다. 무거운 검증(PGlite·codex)은 전경에서 하나씩. aside 스크린샷이 CDP 타임아웃이면 375px iframe 수치 측정으로 대신한다.

## Worker 만 바꾼 첫 이슈 회고 (이슈 #2, 2026-10-19~21)
운영에서만 나는 실패는 테스트로 재현이 안 된다. 엣지 probe(`wrangler dev --remote` 로 어댑터를 그대로 실행)로 원인을 가르고, 재현 못 한 소스(더팀스)는 고치지 말고 오류 기록부터 늘려 다음 Cron 에서 원인을 읽었다(→ 하루 뒤 봇 차단 확인). 그래서 Worker·DB 만 바꾼 이슈는 "다음 Cron 확인"에서 멈추고, 확인이 한 번에 안 끝날 수 있다(2차 수정 1회). 같이 배운 것: 통합 테스트 T9-2b 는 plan 의 SCHEDULE 코드 블록을 안 본다 — 문서 정합은 교차검증 초점으로.

## 첫 시험 회고 (이슈 #1, 2026-10-16~19)
한 줄 문구 변경에 사람 개입 9번(티켓 확인 · G0 · 구현 시작 · 배포 시작 · push 확인 2 · 실기기 · 검수 질문 · 검수 hook), 문서 커밋 5개. 꼭 필요했던 건 실기기와 검수 hook 2개뿐이었다 → `/flow` 로 1~4단계를 잇고, push 게이트를 빼고, `/flow-submit` 호출을 실기기 통과 선언으로 바꿨다. 같이 고친 것: 콘솔 ID 를 런북 5절에 적음, 릴리스 노트는 `bundle_submit_review` 에 바로 넣음, 상태 줄은 Edit 도구로 고침(sed 가 이모지에서 조용히 실패).
