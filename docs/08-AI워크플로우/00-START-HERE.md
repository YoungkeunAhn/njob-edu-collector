# 08-AI워크플로우 — 진입점

수정사항·변경사항을 GitHub 이슈에서 출발해 토스 검수요청까지 가져가는 AI 작업 흐름이다.

## 기본 경로 — 사람 손이 닿는 곳은 2번

```
/flow <변경사항>   →  티켓 → 계획 → 구현·테스트 → push·빌드·테스트 푸시   ⏸ 실기기 확인
/flow-submit #N    →  검수요청(hook 확인 1회)                                ⏸ 검수 결과 → 콘솔 "출시하기"
/flow-close #N     →  backlogs 문서를 docs 정본으로 이관 → 폴더 삭제 → 이슈 닫기
```

- Worker·DB 만 바뀐 작업은 `/flow` 가 다음 Cron 결과 확인에서 멈추고, 확인되면 바로 `/flow-close #N`(검수요청 없음).

- `/flow` 는 1~4단계를 **멈추지 않고** 진행한다. 정할 것(티켓의 빈 칸 · 계획의 Q · 운영 Worker/DB 배포)이 있을 때만 계획을 다 쓴 뒤 **한 번에 모아** 묻고, 답을 받으면 끝까지 간다.
- 작은 변경(노드 1개 · Q 0개 · DB 없음)은 계획 문서·검증·기록을 축약한다(`.claude/skills/flow/SKILL.md`).
- `/flow-submit #N` 을 부르는 것이 곧 "실기기 확인 통과"다. 실패면 `/flow-submit #N <실패 내용>` → 검수요청 대신 이슈에 남기고 재구현.
- 검수 반려는 **새 이슈로** 다시 `/flow` (반려 사유를 이슈에 그대로 남긴다).

## 단계 (개별 스킬 — 재개·큰 작업용)

| 단계 | 스킬 | 하는 일 | 산출물 |
|---|---|---|---|
| 1. 티켓 | `/flow-ticket` | 변경사항을 [티켓 양식](01-티켓-양식.md)으로 정리해 `gh issue create` | GitHub 이슈 `#N` |
| 2. 계획 | `/flow-plan #N` | `graph-plan` 으로 실행 그래프 작성 | `backlogs/NNN-이슈<N>-<요지>/00-START-HERE.md` |
| 3. 구현 | `/flow-impl #N` | 노드별 구현·테스트·커밋(노드 1개 = 커밋 1개) → `/code-review` | 노드 커밋들 |
| 4. 배포·테스트 | `/flow-ship #N` | push → [배포 런북](../07-운영/배포-런북.md) 순서(DB → `wrangler deploy` → `ait build`) → 번들 업로드 → 토스 테스트 푸시 | Worker 버전·앱 번들 번호 |
| 5. 검수요청 | `/flow-submit #N` | 릴리스 노트와 함께 토스 검수요청 → 기록 | 검수 요청 기록 |
| 6. 마무리 | `/flow-close #N` | 결정 → plan 「결정 기록」, 운영 주의 → 런북·소스 문서, 방법론 → 이 폴더 회고. 나머지는 이슈 마감 댓글. 백로그 폴더 삭제 · 이슈 닫기 | docs 반영 커밋 · 닫힌 이슈 |

`/flow` 가 중간에 멈췄을 때(실패·보고) 그 단계 스킬로 이어서 한다. 노드가 여러 개거나 운영 DB 를 바꾸는 큰 작업은 단계마다 결과를 보고 싶으면 개별 스킬로 돌린다.

스킬·라벨·hook 게이트 상세: [02-스킬과-게이트.md](02-스킬과-게이트.md)

## 규칙
- 무엇을 할지는 **이슈**, 어떻게 할지는 **`backlogs` 문서**가 정본이다. `backlogs` 는 진행 중인 일만 둔다 — 끝나면 `/flow-close` 로 docs 에 남길 것만 옮기고 지운다.
- 이슈 라벨로 단계를 표시한다(`stage:ticket` → … → `stage:testing` → `stage:review`). 개별 스킬은 앞 단계 라벨이 없으면 시작하지 않는다.
- 사람 확인은 **사람만 할 수 있는 일(실기기)** 과 **되돌릴 수 없는 외부 동작(검수요청)** 에만 둔다.
- 상태 줄·인덱스 표는 Edit 도구로 고친다(sed 는 이모지에서 조용히 실패한다).
