### 키를 받으면 먼저 드라이런 (🟡 검증)

대구·K-Startup·표준데이터·온통청년은 공식 문서 필드로 만든 **합성 픽스처**로 구현했다. 키를 받으면 실제 응답으로 확인한다. DB에는 쓰지 않는다.

키는 `worker/.dev.vars`에 넣는다(`.dev.vars.example`을 복사, 커밋 안 됨). 드라이런과 `wrangler dev`가 같은 파일을 읽는다. 운영 Worker에는 4절에서 `wrangler secret put`으로 따로 넣는다.

```bash
npm run dry-run -w worker -- seoul-yeyak daegu kstartup lifelong-std kmooc youthcenter
```

- 소스마다 `OK 받음 N · 저장 N · 분류됨(노출) N`이 나오면 통과.
- `응답 형식`·`총건수 없음`·`날짜 형식`·`모르는 상태` 같은 오류가 나면 실제 응답이 문서와 다른 것이다. 해당 어댑터(`worker/src/sources/<code>.ts`)와 픽스처(`worker/test/sources/fixtures/`)를 실응답으로 고친다. 각 어댑터 머리 주석에 확인할 항목이 적혀 있다.
- 키 없이 되는 소스는 인자 없이 `npm run dry-run -w worker`로 언제든 돌려 볼 수 있다(2026-10-12 결과는 실행 그래프 N9 절).

확인:

### 첫 수집을 기다리지 않고 돌려 보기

로컬에서 실제 Supabase를 대상으로 Cron 하나를 흉내 낸다. `worker/.dev.vars`를 `.dev.vars.example`대로 채운 뒤:

```bash
cd worker && npx wrangler dev --test-scheduled
# 다른 터미널
curl "http://localhost:8787/__scheduled?cron=20+18+*+*+*"   # B 그룹(정적 HTML 4개)
```

- 고용24(`0 18 * * *`)는 약 10분 걸린다.
- AI디지털배움터(`40 18 * * *`)는 Browser Rendering 바인딩이 있어야 해서 배포 후 03:40(KST) 실행 결과로 확인한다.

결과는 Supabase에서 본다.


## 5-0. 한글 CLI 입력과 번들 메모 확인(필수 배포 관문)

2026-10-27 테스트 번들 등록 중 PowerShell에서 전달한 한글 메모가 깨진 사례를 반영한다. 콘솔의 등록 메모를 수정할 수 없는 경우가 있으므로 **UTF-8 원문 파일 → 로컬 전달 검사 → 등록 → 동일 deploymentId 메모 대조**를 매번 적용한다. 이는 자동 검증 단계이며 별도 사용자 승인 단계가 아니다.

### 입력 파일과 프로세스 실행

- 프롬프트·업로드 메모는 UTF-8 파일로 보관한다. PowerShell의 콘솔 입력·출력과 `$OutputEncoding`도 UTF-8로 설정하되, 문자열 파이프의 인코딩 설정만으로 전달 성공을 판단하지 않는다.
- 모든 CLI 한글 프롬프트는 공통 실행 래퍼 claude-utf8.mjs에 **파일 경로**로 전달한다. PowerShell에서는 Invoke-ClaudeUtf8.ps1을 사용한다. `Get-Content ... | claude ...`처럼 PowerShell 문자열을 CLI stdin에 직접 파이프하는 패턴을 재사용하지 않는다. 명령행 인자에 한글 프롬프트를 펼치거나 ASCII 문구로 조용히 대체하지 않는다.
- Node 실행부가 파일을 UTF-8 바이트로 읽어 자식 프로세스 stdin에 직접 쓴다. `shell: false`, `windowsHide: true`를 유지하고, 추가 터미널 창·`Start-Process`의 보이는 창을 만들지 않는다. PowerShell 래퍼는 UTF-8 설정과 경로 전달만 담당한다.
- Claude로 토스 MCP를 사용할 때는 `--strict-mcp-config`와 **토스 콘솔 서버만 담은 MCP 설정 파일**을 사용한다. 다른 연결 서버나 불필요한 백그라운드 프로세스를 함께 시작하지 않는다. 인증값이 있는 설정·임시 응답은 커밋하거나 화면에 출력하지 않는다. 메모 검증용 출력은 `--output-format stream-json --verbose`로 실제 도구 호출·결과를 담은 원시 stdout trace를 저장한다. `text` 출력이나 모델의 최종 JSON 설명은 등록값 증거로 쓰지 않는다.
- 일반 `run`의 등록·조회 단계는 코드에서 `--permission-mode dontAsk`와 정확한 도구 허용 목록을 강제하고, `bundle_test_push`·검수 요청은 차단한다. 전역 `bypassPermissions`나 프롬프트의 금지 문구에 의존하지 않는다. 출시 도구 이름을 추정해 차단 목록을 만드는 대신 허용 목록 밖의 변경 도구를 사용할 수 없게 한다. 검증 후 테스트 푸시는 아래 전용 `test-push` 명령으로만 실행한다.
- CLI에는 `--setting-sources ''`(빈 문자열)를 고정해 user·project·local 설정의 광범위한 `permissions.allow`가 병합되지 않게 한다. 관리형 정책은 그대로 존중하며, `run`·`test-push`에서는 검수 도구 자체를 차단한다. 검수 승인 hook과 별도 검수 워크플로우는 변경하지 않는다.

### 등록과 원문 대조 순서

1. 메모 원문은 한 줄, 1~120자로 확정하고 파일로 저장한다. 래퍼는 UTF-16 길이로 한도를 검사하고 `??`·유니코드 대체문자를 거절한다. 파일 끝의 개행 한 개만 제거하며, 검증한 메모를 프롬프트의 `Exact external memo` JSON 문자열 블록으로 직접 추가한다. 등록 시 이 문자열을 그대로 사용한다.
2. 공통 래퍼의 로컬 한글 전달 검사를 통과시킨다. 입력 파일의 UTF-8 유효성을 확인하고, 실제 CLI와 같은 전송 함수로 한글·기호·이모지·줄바꿈을 포함한 검사 문자열을 로컬 자식 프로세스에 보내 왕복 바이트가 일치하는지 확인한다. 표시상 한글이 읽힌다는 이유만으로 통과시키지 않는다. 실제 등록 메모의 일치는 4단계에서 별도로 검증한다.
3. 사전 검사 통과 뒤 `bundle_upload`로 이번 `deploymentId`와 메모를 등록하고, 바이너리를 `uploadUrl`에 PUT → `bundle_upload_complete` → `bundle_build_status`로 완료를 확인한다. **PREPARE 상태는 `bundle_list`에 나타나지 않을 수 있고 실제 확인에서도 미노출됐다.** 등록 메모 조회를 위해 업로드 완료·CREATED 상태까지 진행해야 한다.
4. 완료 후 `bundle_list` 조회를 별도 실행하고 `stream-json --verbose`의 **원시 stdout trace 파일**을 그대로 `verify-memo --actual`에 넘긴다. 검증기가 정확한 `mcp__apps-in-toss-console__bundle_list` 호출의 `tool_use.id`와 `tool_result.tool_use_id`를 연결하고, 호출 입력의 workspaceId·miniAppId가 대상 앱과 일치하는지 확인한 뒤 실제 도구 응답에서 이번 deploymentId의 메모를 찾아 원문과 대조한다. 모델의 assistant/result 설명·최종 JSON·직접 추출하거나 재작성한 객체는 증거로 받지 않는다. 해당 도구 결과·앱·번들을 찾지 못하거나 메모가 다르면 실패다.
5. 대조 성공 뒤 전용 `test-push` 명령으로 `bundle_test_push`를 진행한다. 이 명령도 원문 메모·원시 trace·대상 ID를 다시 검증한 후 정확한 앱·deploymentId로 고정된 프롬프트와 ToolSearch·번들 조회·테스트 푸시만 허용한 도구 목록을 사용한다. 대조를 통과하지 않은 번들의 테스트 요청·검수 요청·공개 출시를 진행하지 않는다. `bundle_upload` 응답에서 메모를 실제로 반환하는 경우 추가 대조는 가능하지만, 응답에 그 필드가 있다고 가정하지 않는다.
6. 기록에는 deploymentId·번들 번호·로컬 전달 검사·메모 대조 결과·업로드 완료·테스트 요청 결과를 구분해 남긴다. 테스트 요청 성공은 실기기 테스트 통과가 아니며, 기존 5절의 실기기 관문을 유지한다.

로컬 전달 검사가 실패하면 등록하지 않는다. 등록 메모 대조가 실패하면 현재 상태와 deploymentId를 보고하고 테스트 요청·검수·출시를 멈춘다. 메모를 고칠 수 없다고 자동으로 중복 업로드하거나 새 번들을 등록하지 않는다. 등록 메모가 확인되지 않은 상태를 ASCII 대체 문구로 우회하지 않는다.

### 공통 래퍼 실행 예시

레포 루트에서 실행한다. 아래 `$releaseDir` 디렉터리를 만들고 UTF-8 프롬프트·메모 파일과 토스 서버만 지정한 `toss-mcp.json`, 단계별 추가 인자 JSON 파일을 먼저 준비한다. UTF-8 BOM은 허용하지만 잘못된 UTF-8·NUL·대체문자는 거절한다. 프롬프트에는 이번 단계에서 할 작업만 넣고, 등록·완료 단계에서 테스트 푸시까지 한 번에 지시하지 않는다.

출력 디렉터리는 미리 존재해야 한다. `--output` 파일과 자동 생성되는 `<output>.stderr`는 **기존 파일이 있으면 거절**하므로 단계별로 새 파일 이름을 사용한다. `--check-only`는 두 파일을 만들지 않아 바로 다음 실제 실행에 같은 출력 경로를 사용할 수 있다. 입력 파일과 출력 파일의 경로도 같으면 안 된다.

실제 Claude 호출의 `--args` 파일은 **추가 인자만** 받는다. `-p`, `--no-session-persistence`, `--strict-mcp-config`, `--setting-sources ''`, `--permission-mode dontAsk`, `--output-format stream-json`, `--verbose`와 위험 도구 차단은 코드가 강제한다. 파일에는 `--mcp-config`와 `run`의 `--allowedTools`만 넣고, 보호 옵션을 중복 지정하거나 와일드카드를 사용하지 않는다. MCP 파일 경로는 실제 절대 경로로 바꾼다.

등록·완료용 `upload-args.json` 예시:

```json
["--mcp-config", "C:/release/toss-mcp.json", "--allowedTools", "ToolSearch,mcp__apps-in-toss-console__bundle_upload,mcp__apps-in-toss-console__bundle_upload_complete,mcp__apps-in-toss-console__bundle_build_status"]
```

원문 대조를 위한 조회 전용 `list-args.json` 예시:

```json
["--mcp-config", "C:/release/toss-mcp.json", "--allowedTools", "ToolSearch,mcp__apps-in-toss-console__bundle_list"]
```

기본 제공 도구도 Read·Write·Glob·Grep·ToolSearch로 제한하며 셸·코드 실행 도구는 노출하지 않는다. 허용 목록은 해당 단계에 필요한 항목만 적는다. 바이너리 PUT은 배포 오케스트레이터가 기존 업로드 절차로 수행한다.

```powershell
$releaseDir = Join-Path $env:TEMP 'njob-release'

# 외부 CLI·MCP를 호출하지 않는 로컬 파일·한글 전달 검사. 등록 전 필수.
./scripts/Invoke-ClaudeUtf8.ps1 run --prompt "$releaseDir/upload-prompt.txt" --memo "$releaseDir/memo.txt" --args "$releaseDir/upload-args.json" --output "$releaseDir/upload-trace.jsonl" --check-only
if ($LASTEXITCODE -ne 0) { throw 'UTF-8 preflight failed' }

# 검사를 통과한 동일 파일로 해당 단계 실행. 출력도 UTF-8 파일에 저장한다.
./scripts/Invoke-ClaudeUtf8.ps1 run --prompt "$releaseDir/upload-prompt.txt" --memo "$releaseDir/memo.txt" --args "$releaseDir/upload-args.json" --output "$releaseDir/upload-trace.jsonl"
if ($LASTEXITCODE -ne 0) { throw 'CLI step failed' }
```

Node에서 직접 실행해도 같은 계약이다: `node scripts/claude-utf8.mjs run --prompt <UTF8파일> --memo <메모파일> --args <추가인자JSON파일> --output <결과파일>`. `--executable`의 실제 CLI는 `claude`·`claude.exe`만 허용하며, 로컬 테스트용으로는 현재 Node 실행 파일의 정확한 절대 경로만 허용한다. 다른 셸·`.cmd`·이름을 바꾼 CLI로 보호 옵션을 우회하지 않는다.

업로드 완료 후 `bundle_list`를 조회하는 별도 실행의 원시 출력 파일을 `bundle-list-trace.jsonl`로 보관한다. 이 파일은 `--output-format stream-json --verbose`로 실행한 stdout 원본이어야 하며, 도구 결과에서 JSON을 수동 추출하거나 모델에게 다시 작성시키지 않는다. 성공 종료 결과가 없는 불완전한 trace도 검증에 실패한다. 등록 완료 응답이나 프롬프트에 적힌 메모도 대조 증거가 될 수 없다.

```powershell
$deploymentId = '<이번 ait build의 deploymentId>'
./scripts/Invoke-ClaudeUtf8.ps1 run --prompt "$releaseDir/list-prompt.txt" --args "$releaseDir/list-args.json" --output "$releaseDir/bundle-list-trace.jsonl"
if ($LASTEXITCODE -ne 0) { throw 'Bundle list failed' }
node scripts/claude-utf8.mjs verify-memo --expected "$releaseDir/memo.txt" --actual "$releaseDir/bundle-list-trace.jsonl" --deployment-id $deploymentId --workspace-id 52463 --mini-app-id 85989
if ($LASTEXITCODE -ne 0) { throw 'Registered memo mismatch: stop before test push' }
```

원문 대조 성공을 기록한 뒤 테스트 푸시를 별도 단계로 호출한다. 일반 `run`에서 테스트 푸시 차단을 해제하거나 임의 프롬프트로 대신 호출하지 않는다. 전용 명령은 외부 호출 전에 같은 메모·trace·대상 ID를 재검증하며, 사용자 프롬프트 없이 검증된 대상만 넣은 고정 프롬프트를 사용한다. `test-push-args.json`에는 아래처럼 `--mcp-config`만 넣는다. 전용 명령의 도구 허용 목록은 코드가 정하므로 `--allowedTools`도 지정할 수 없다.

```json
["--mcp-config", "C:/release/toss-mcp.json"]
```

```powershell
node scripts/claude-utf8.mjs test-push --expected "$releaseDir/memo.txt" --actual "$releaseDir/bundle-list-trace.jsonl" --deployment-id $deploymentId --workspace-id 52463 --mini-app-id 85989 --args "$releaseDir/test-push-args.json" --output "$releaseDir/test-push-trace.jsonl"
if ($LASTEXITCODE -ne 0) { throw 'Test push failed: inspect the saved trace' }
```

이 명령의 원시 결과에서 해당 대상에 대한 테스트 요청 성공을 확인한다. 실기기 확인·검수·공개 출시는 기존 절차를 따른다. UTF-8 관문 자체를 검증하는 작업에서는 실제 등록·업로드·테스트 푸시를 실행하지 않는다.

### 6-1. 로컬 수집 (잡아바·주변애·더팀스)

Cloudflare 에서 나가는 요청을 막는 소스는 이 PC 가 수집한다(plan D20). Worker 와 같은 `runGroup` 이라 `collect_run` 기록·급감 판단·텔레그램 알림이 똑같이 남는다.

- 수동 실행: `npm run collect-local -w worker` (`.dev.vars` 의 `SUPABASE_*`·`TELEGRAM_*` 사용). 로그는 `worker/collect-local.log`
- 작업 스케줄러 `njob-collect-local`: 매일 03:30, 놓치면 PC 가 켜질 때 바로 실행(StartWhenAvailable). 다른 PC 로 옮길 때 다시 등록:
  ```powershell
  $a = New-ScheduledTaskAction -Execute "cmd.exe" -Argument "/c npm run collect-local >> collect-local.log 2>&1" -WorkingDirectory "<레포>\worker"
  $s = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Minutes 30) -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries
  Register-ScheduledTask -TaskName "njob-collect-local" -Action $a -Trigger (New-ScheduledTaskTrigger -Daily -At 03:30) -Settings $s
  ```
- PC 가 며칠 꺼져 있어도 지워지는 건 없다. 마감 지난 행은 Worker 후처리가 지우고, 새 강좌만 늦게 들어온다. 마지막 실행은 `select * from collect_run where source in ('jobaba','greenlove','theteams') order by started_at desc limit 3;`

### 알아 둘 동작

- **view 를 바꾸는 배포는 DB 먼저**: 마이그레이션(`supabase db push` 또는 SQL Editor) → `wrangler deploy` → 앱. Worker 가 view 에 없는 컬럼을 select 하면 목록이 전부 500 이 된다(예: `20261014000002` 의 `capacity`·`price_sort`·`title_norm`).
- 목록·상세 응답은 1시간, 상세 보강(`/courses/:id/extra`)은 6시간 캐시된다. 원천 링크를 고친 배포 뒤에도 최대 1시간은 캐시된 목록에 옛 링크가 남을 수 있다(2026-10-14 고용24 링크 사례).
- 상세 보강은 사용자가 고용24 강좌 상세를 열 때 고용24 페이지를 2번(상세 약 400KB·교과편성 약 6KB) 부른다. 같은 강좌는 6시간 캐시. 고용24 구조가 바뀌면 인원·커리큘럼 칸만 비고 나머지는 그대로다 — `worker/src/sources/work24-detail.ts` 와 픽스처를 고친다.

- **Cloudflare IP 차단**: 로컬 curl 은 되는데 운영만 403·WAF·`Just a moment...` 이면 원천이 Cloudflare 에서 나가는 요청을 막는 것이다. `collect_run.error` 의 `[server=…]` 와 본문 앞 120자로 누가 막았는지 본다. 재현은 `wrangler dev --remote`(엣지에서 실행)로 한다 — 그래도 막히면 우회하지 않고 `SCHEDULE` 에서 `LOCAL` 로 옮긴다(plan D20, 6-1절).
- **AI디지털배움터 목록 열기**: 페이지가 계속 요청을 보내 `networkidle`·`load` 에 닿지 않는다 → `domcontentloaded` + 사이트 함수 준비 대기. 새벽 첫 열기가 가끔 30초를 넘겨 열기만 1회 다시 한다. 5천여 건이라 넘기는 사이 총건수가 바뀌면 처음부터 1회 다시 받는다(전체 약 90초).
- **새싹 일시 장애 재시도**: 2026-10-26 03:20(KST)에 `HTTP 530 / error code: 1016`이 발생했고, 같은 날 로컬·Cloudflare 재검증에서는 14건을 정상 수집했다. 새싹의 페이지 요청은 5xx·네트워크 오류·시간 초과에 한해 2초·4초 뒤 최대 2회 재시도한다(시도마다 30초 제한). 계속 실패하면 실패 기록과 알림을 남기고 부분 저장·미노출 정리를 하지 않는다. 403 등 4xx는 재시도하지 않는다.
- **온통청년 키·실응답 확인(2026-10-26)**: Aside의 로그인된 프로필에서 기존 청년정책API 신청이 2026-10-13 승인됐고 키 유효기간이 2027-10-13까지임을 확인했다. 발급은 완료됐지만 수집기 설정에 빠져 있어 기존 키를 `.dev.vars`와 Worker의 `YOUTHCENTER_API_KEY`에 등록했다. 갱신 전 [마이페이지 OPEN API](https://www.youthcenter.go.kr/myPage/openapi)에서 확인한다. 실제 응답은 `result.youthPolicyList`이고 `pageSize=1000`을 지원한다. 5xx·네트워크·시간 초과는 2초·4초 뒤 최대 2회 재시도한다. 신청기간의 `\\N` 구분은 현재 접수 구간을 선택하며, 구간 사이에는 모집중으로 노출하지 않는다. 신청URL의 `전화문의`는 참조URL로 대체하고 참조도 없으면 제외한다. 인증 오류·잘못된 응답·수집 중 총건수 변경은 계속 실패로 처리해 기존 행을 보호한다.
- 마감일(없으면 교육 시작일)이 지난 강좌는 매일 04:00 후처리에서 지운다.
- 원천에서 사라진 강좌는 **수집이 성공하고 건수가 직전의 50% 이상일 때만** 지운다. 실패·급감·정규화 실패가 있으면 지우지 않고 알린다.
- 원천 전체 목록을 확인할 수 없거나 행을 하나씩 구분할 수 없는 소스 3개(서울시평생학습포털·데브이벤트·전국평생학습강좌표준데이터)는 "사라진 행" 정리를 하지 않는다. 취소된 강좌가 날짜가 지날 때까지 남을 수 있다.
- 키워드 분류에 안 걸린 강좌는 저장하지만 노출하지 않는다. 강좌가 아닌 공고가 걸리는 경우가 있다(예: 지원사업 공고) — 위 "분류 고치기".
