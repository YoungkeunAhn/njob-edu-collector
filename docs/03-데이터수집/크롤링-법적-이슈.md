# 크롤링 법적 이슈 (한국) — 실무 가이드

- 작성일: 2026-10-11 / 담당: E
- 법률 자문이 아니다. 법무법인 뉴스레터·기사·법령 정보 사이트를 근거로 정리했다. 출시 전에 변호사 검토를 1회 받는 것을 권한다.

## 결론 먼저

1. **공공 API·공공누리 1유형 데이터가 1순위.** 공공데이터법 제3조 제4항이 영리적 이용도 보장한다.
2. 크롤링을 하더라도 **"목록 메타데이터(제목·기관·일정·지역·비용) + 원문 링크"만** 가져간다. 설명문 전문, 이미지, 후기는 복제하지 않는다.
3. 로그인 뒤 페이지, 차단 우회, 비공개 API 호출, 과도한 요청은 법적 위험이 커지는 요소다. 다만 **소스를 미리 제외하지 않는다.** robots.txt·약관 제약은 [소스별-수집가능성-목록.md](소스별-수집가능성-목록.md)에 사실로 기록하고, 넣을지 말지는 사용자가 정한다.
4. 경쟁 플랫폼(예: 다른 교육 큐레이션 앱)의 DB를 통째로 긁어 같은 서비스를 만드는 것이 가장 위험하다. 형사에서 무죄가 나도 민사(부정경쟁)에서 10억 원 배상이 나온 사례가 있다.

## 1. 관련 법

### 1-1. 저작권법 – 데이터베이스제작자의 권리 (제91조~제98조)
- 제93조: DB의 **전부 또는 상당한 부분**의 복제·배포·전송 권리는 DB제작자에게 있다. 개별 소재 하나는 상당한 부분이 아니지만, **반복적·체계적으로** 복제해 DB의 통상적 이용과 충돌하거나 제작자 이익을 부당하게 해치면 상당한 부분 복제로 본다. (조문 요지. 원문은 국가법령정보센터 확인 필요)
- 대법원 2021도1533(여기어때 형사)의 판단 기준: "상당한 부분"은 양적·질적으로 본다. 질적 판단은 개별 소재 가치가 아니라 **DB 제작·갱신·검증·보충에 들인 상당한 투자**가 기준이다. 반복적·체계적 복제는 "결국 상당한 부분의 복제등을 한 것과 같은 결과를 발생하게 한 경우에 한하여" 인정한다.
- 개별 강좌의 사실 정보(강좌명, 일정, 장소, 비용)는 저작물로 보기 어렵다. 다만 **강좌 소개글·썸네일 이미지**는 저작물일 수 있어 그대로 복제하면 별도 저작권 침해 소지가 있다.

### 1-2. 부정경쟁방지법 – 제2조 제1호 (카)목 데이터 부정사용
- 2021년 개정, **2022-04-20 시행**으로 신설. 2024-02-20 개정으로 보호 데이터 요건이 "비밀로 관리되지 않는 정보"에서 "영업비밀을 제외한 정보"로 바뀌었다(2024년 개정법 시행일 미확인).
- 보호 대상 데이터: "업으로서 특정인 또는 특정 다수에게 제공되는 것으로, 전자적 방법으로 상당량 축적·관리되는 기술상 또는 영업상의 정보(영업비밀 제외)"
- 금지 행위(요지): ① 접근권한 없는 자가 절취·기망·부정접속 등 부정한 수단으로 취득·사용·공개 ② 계약 등으로 접근권한이 있는 자가 부정한 이익 목적으로 사용·제3자 제공 ③ ①②를 알고 취득·사용 ④ 기술적 보호조치를 무력화하는 기술·서비스 제공
- 실무 의미: **로그인·유료회원 전용 데이터**, 차단을 우회해 가져온 데이터가 위험하다. 누구나 보는 공개 목록 페이지를 적정 속도로 보는 것은 ①의 "부정한 수단"과 거리가 멀다(해석).
- 별도로 기존 성과물 도용 조항(현행 (파)목, 구 (카)목)으로도 다툼이 가능하다. 여기어때 민사 판결이 부정경쟁행위를 인정한 사례다. 이 판결이 어느 목에 근거했는지는 미확인.

### 1-3. 정보통신망법 제48조 제1항 – 정보통신망 침입
- "정당한 접근권한 없이 또는 허용된 접근권한을 넘어" 정보통신망에 침입 금지.
- 대법원 2021도1533: 접근권한은 **서비스 제공자가 부여한 권한** 기준이며, **보호조치나 이용약관 등 객관적으로 드러난 사정**으로 접근을 제한했는지로 판단한다. 해당 사건에서는 API 서버 URL을 패킷캡쳐로 쉽게 알 수 있었고 별도 보호조치가 없었으며, 약관 제한이 비회원에게 적용되기 어려웠고, 수집 정보가 공개 정보였다는 이유로 침입을 부정했다.
- 뒤집어 읽으면: **명시적 차단·인증·약관상 금지가 있으면** 같은 행위라도 침입이 인정될 여지가 있다.

### 1-4. 형법 컴퓨터등장애업무방해 (제314조 제2항)
- 대법원 2021도1533: 실제 정보처리 장애가 발생해야 한다. 서비스 장애가 특정일 이용자 증가 탓일 수도 있어 피고인 책임으로 보지 않았다.
- 실무 의미: 요청 간격을 두고 야간에 소량 수집하면 위험이 낮다. 상대 서버 장애를 일으키면 이 조항과 민사 책임이 모두 문제된다.

### 1-5. 개인정보보호법
- 강사명, 담당자 휴대전화 등은 개인정보다. 강좌 매칭에 필요 없으므로 **수집하지 않는다**(공공 API의 `instrctrNm` 등도 저장하지 않거나 화면에 안 쓴다). 기관 대표번호만 쓴다.

## 3. robots.txt

- 한국 법에 robots.txt 준수를 직접 강제하는 조문은 없다(확인 범위 내).
- 그러나 판례는 접근권한을 "보호조치·이용약관 등 객관적 사정"으로 판단한다. robots.txt의 Disallow는 **사이트 운영자가 기계적 접근을 원치 않는다는 객관적 표시**로 쓰일 수 있다(해석). 지키지 않으면 분쟁 시 불리하다.
- 원칙: robots.txt Disallow 경로는 수집하지 않는다. User-Agent에 서비스명과 연락처를 넣는다.

## 4. 상업적 이용 시 체크리스트

수집 소스를 추가할 때마다 아래를 확인하고 소스 레지스트리에 기록한다.

- [ ] 공식 API나 공공누리 1·3유형 데이터가 있나? 있으면 그걸 쓴다.
- [ ] 이용약관에 자동수집·크롤링·상업적 이용 금지 조항이 있나? 있으면 조항을 기록한다(포함 여부는 사용자가 결정).
- [ ] robots.txt가 해당 경로를 막나? 막으면 막힌 경로를 기록한다.
- [ ] 로그인 없이 누구나 볼 수 있는 페이지인가?
- [ ] 가져가는 필드가 사실 정보(제목·기관·기간·장소·비용·대상·URL)뿐인가? 설명문 전문·이미지·후기는 빼기.
- [ ] 요청 속도: 사이트당 동시 1개, 요청 간 1~3초 이상, 하루 1회 야간.
- [ ] 개인정보(강사명·휴대전화) 미수집.
- [ ] 화면에 출처 기관명과 원문 링크를 붙였나?
- [ ] 운영자가 삭제를 요청하면 24~72시간 안에 내리는 절차가 있나?

## 5. 출처 표기·원문 링크 방식이 안전한 이유

1. **복제량 최소화**: 메타데이터 몇 개만 보여 주고 상세는 원문으로 보내면 DB의 "상당한 부분" 복제나 "통상적 이용과 충돌"로 보기 어렵다. 판례도 수집 필드 수(50여 개 중 3~8개)를 고려했다.
2. **원 사이트에 손해가 아니라 트래픽을 준다**: 신청은 원문에서 하니 원 기관의 이익을 해치지 않는다. 부정경쟁 판단의 핵심인 "경쟁 관계에서 성과 무단 사용"과 거리가 멀다. 대부분의 공공·평생교육 기관은 수강생 모집이 목적이라 오히려 환영할 가능성이 높다.
3. **라이선스 의무 이행**: 공공누리 모든 유형이 출처표시를 요구한다.
4. **정확성 책임 분산**: 일정·비용이 바뀌어도 "최종 정보는 원문 기준" 고지와 링크로 사용자 피해를 줄인다.

- 수집 데이터를 제3자에게 재판매
