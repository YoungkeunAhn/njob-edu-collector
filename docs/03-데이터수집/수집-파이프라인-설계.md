# 수집 파이프라인 설계 (최소 권장안)

> **확정 내용은 [../06-스펙/plan.md](../06-스펙/plan.md)를 따른다.** 이 문서와 다른 점: 마감된 강좌는 수집·보관하지 않는다(3일 미노출 규칙과 `status` 컬럼은 폐기). 분류는 키워드 룰만 쓰고 LLM은 쓰지 않는다. 수집은 Cloudflare Worker Cron으로 돌리고 언어는 TypeScript다.

- 작성일: 2026-10-11 / 담당: E
- 원칙: 하루 1번 돌고, 실패해도 어제 데이터가 남아 있으면 된다. 큐·워커·스트리밍은 쓰지 않는다.

## 1. 전체 흐름

```
[cron 매일 03:00 KST]
   └─ 소스별 어댑터 실행 (순차, 소스 하나 실패해도 다음 진행)
        fetch → 원본 저장(raw_json) → normalize() → 공통 Course 레코드
   └─ upsert (source, source_id 기준)
   └─ 마감 처리 (상태 갱신)
   └─ 카테고리 분류 (규칙 → 미분류만 LLM)
   └─ 지역 코드 매핑 (주소 → 시군구 코드)
   └─ 소스별 수집 건수 로그 → 전일 대비 50% 이상 급감하면 알림
```

- 실행 환경: 서버리스 cron(Vercel Cron, GitHub Actions schedule 등) 또는 VM의 crontab 중 하나. DB는 Postgres 1개.
- 소스가 5~10개 수준이면 순차 실행으로 충분하다. 고용24는 페이지당 100건 × 필요한 만큼 페이지.

## 2. 소스 어댑터

어댑터 = 함수 2개. 클래스 계층·플러그인 시스템은 만들지 않는다.

```python
# sources/seoul_yeyak.py
SOURCE = "seoul_yeyak"
def fetch() -> list[dict]: ...           # 원본 레코드 목록
def normalize(raw: dict) -> dict: ...    # 공통 스키마 dict
```

`main.py`에 `SOURCES = [work24, lifelong_std, seoul_yeyak, kmooc, ...]` 리스트 하나를 두고 돈다.

| 소스 | 증분 방법 | 고유키 | 마감 판단 |
|---|---|---|---|
| 고용24 훈련과정 | `srchTraStDt`=오늘 ~ `srchTraEndDt`=오늘+90일, `srchTraProcessNm`에 AI 키워드 여러 번 | `trprId` + `trprDegr` | 훈련시작일 지남 (접수기간 필드 없음) |
| 평생학습강좌 표준데이터 | 전체 재수집(분기 갱신이라 주 1회로 충분) | `instt_code` + `lctreNm` + `edcStartDay` 해시 (원천 ID 없음) | `rceptEndDate` 지남 |
| 서울 공공서비스예약 교육 | 전체 재수집(수백 건) | `SVCID` | `SVCSTATNM` ≠ 접수중, 또는 `RCPTENDDT` 지남 |
| K-MOOC | 전체 재수집 | 강좌코드 | 학습기간 종료 |
| AI디지털배움터 | 헤드리스 브라우저(Playwright)로 목록 페이지를 열고 `POST /api/edc/req/list.do` 응답 JSON을 가로챔 (토큰 헤더를 페이지가 직접 붙이므로 따로 만들 필요 없음) | 응답 JSON의 강좌 ID | 응답의 접수 상태·날짜 |
| 크롤링 소스 | 목록 1~N 페이지 | 원문 URL의 ID 파라미터, 없으면 URL 정규화 해시 | 페이지 상태 문구 또는 날짜 |

## 3. 공통 강좌 스키마 (테이블 1개 + 소스 테이블 1개)

```sql
create table course (
  id              bigserial primary key,
  source          text not null,          -- 'work24', 'seoul_yeyak' ...
  source_id       text not null,          -- 원천 고유키
  title           text not null,
  course_type     text not null,          -- 'oneday'(원데이 클래스) | 'training'(교육훈련)
  provider_name   text,                   -- 운영기관
  category_main   text,                   -- 대분류 코드 (카테고리 문서 참고)
  category_sub    text,                   -- 소분류 코드
  category_by     text,                   -- 'rule' | 'llm' | 'manual'
  mode            text,                   -- 'online' | 'offline' | 'blended'
  sido_code       char(2),                -- 법정동코드 앞 2자리, 온라인은 null
  sigungu_code    char(5),                -- 법정동코드 앞 5자리
  address         text,
  cost_type       text,                   -- 'free' | 'card'(내일배움카드) | 'partial' | 'paid'
  cost_amount     int,                    -- 원, 모르면 null
  apply_start     date,
  apply_end       date,
  course_start    date,
  course_end      date,
  target          text,                   -- 대상 자격 원문 (예: '경기도민', '만 40세 이상')
  target_tags     text[],                 -- 'youth','senior','career_break','smb','job_seeker','employed','resident_only'
  capacity        int,
  url             text not null,          -- 원문 URL (신청은 여기서)
  status          text not null default 'open', -- 'open' | 'closed' | 'unknown'
  first_seen_at   timestamptz not null default now(),
  last_seen_at    timestamptz not null default now(),
  raw             jsonb,                  -- 원본 레코드 (재정규화용)
  unique (source, source_id)
);
create index on course (status, sido_code, category_main);
```

```sql
create table source (
  code text primary key, name text, kind text,      -- 'api' | 'crawl'
  license text,            -- '공공누리1', '제한없음', '약관확인-허용' 등
  robots_ok boolean, terms_checked_at date, attribution text, enabled boolean default true
);
```

- **기간·가격**: 기간은 `course_start`/`course_end`(+ 접수 `apply_start`/`apply_end`), 가격은 `cost_type` + `cost_amount`. 내일배움카드 과정은 `cost_amount`에 자부담액을 넣고, 모르면 null로 두고 원문 링크로 안내한다.
- **`course_type` 판정**: 소스 기본값을 쓰고, 날짜로 보정한다.
  - 고용24 국비훈련 → `training`
  - 그 밖의 소스 → `course_start = course_end`(하루짜리)면 `oneday`, 아니면 `training`
  - 날짜가 없으면 → 제목에 `원데이`·`특강`·`세미나`·`1일`이 있으면 `oneday`, 아니면 `training`
- 일부러 뺀 것: 강사명, 담당자 연락처(개인정보), 상세 설명 전문(저작권), 이미지. 필요하면 원문 링크로.
- `raw`를 남겨 두면 정규화 로직을 고쳤을 때 재수집 없이 다시 돌릴 수 있다.

## 4. 중복 제거

1. **같은 소스 안**: `unique(source, source_id)` + upsert. 끝.
2. **소스 간** (예: 경기 데이터와 평생학습 표준데이터에 같은 강좌): MVP에서는 하지 않는다. 화면에서 같은 `title` 정규화값 + `provider_name` + `course_start`가 겹치면 하나만 보여 주는 쿼리로 충분하다.
   - 정규화: 공백·특수문자 제거, 소문자, `[모집]`·`(수강생 모집)` 같은 접두어 제거
   - 소스 우선순위(공식 API > 크롤링)로 남길 것을 고른다.
   - 중복이 실제로 문제가 될 때 `dedup_key` 컬럼을 추가한다.

## 5. 마감된 강좌 처리

- 매일 수집 후 한 번에 갱신:
  - `apply_end < today` 또는 (`apply_end` 없음 and `course_start < today`) → `closed`
  - 원천 상태값이 마감이면 → `closed` (서울 `SVCSTATNM` 등)
  - 이번 수집에서 안 보인 레코드(`last_seen_at < 오늘 수집 시작 시각`)는 바로 지우지 말고 **3일 연속 안 보이면** `closed`. 소스 일시 장애로 멀쩡한 강좌가 사라지는 것을 막는다.
- 삭제하지 않고 `closed`로 남긴다. 화면은 `status='open'`만 조회. 90일 지난 closed는 월 1회 삭제(선택).
- "마감 임박" 배지: `apply_end - today <= 3`.

## 6. 지역 코드 표준

- **법정동코드(10자리)**를 쓴다. 앞 2자리 = 시도, 앞 5자리 = 시군구(일반적으로 알려진 구조: 시도 2 + 시군구 3 + 읍면동 3 + 리 2). 원천: 행정표준코드관리시스템(code.go.kr) 법정동코드 전체 파일. 서비스에선 **시도·시군구 2단계만** 저장한다. 읍면동까지 매칭할 필요는 없다.
  - 행정동코드(행정기관코드)는 주민센터 단위라 자주 바뀐다. 주소→코드 변환이 쉬운 법정동이 낫다.
  - 강원·전북 특별자치도 출범 등으로 시도 코드가 바뀐 곳이 있다(신규 코드값은 code.go.kr에서 확인, 본 조사에서 미확인). 코드 파일은 분기 1회 갱신하고 폐지 코드는 신규 코드로 매핑.
- 매핑 방법 (소스별):
  - 주소 문자열 있음(`edcRdnmadr`, `address`): 앞 두 토큰("경기도 수원시", "서울특별시 종로구")을 법정동 파일의 시도·시군구명과 매칭. 실패 시 행정안전부 도로명주소 API 등으로 보정(필요할 때만).
  - 서울 `AREANM`(자치구명): 서울 + 구명으로 매칭.
  - 고용24 `srchTraArea1`/`trngAreaCd`: 고용24 자체 코드라 **법정동코드와 다르다**(예: '41' 경기는 같지만 '12' 전남광주는 다름). 고용24 공통코드 API로 받은 매핑표를 1회 만들어 둔다.
- 온라인 강좌: `sido_code = null`, `mode='online'`. 화면에서 "온라인(전국)"은 모든 지역 결과에 함께 노출.
- 거주지 제한(`resident_only`)은 지역과 별개 태그로 둔다. "서울 강좌"와 "서울시민만 가능"은 다르다.

## 7. 카테고리 자동 분류

1. **키워드 룰 (1차, 무료·결정적)**: `title` + 짧은 설명 앞부분을 정규화해 [카테고리 키워드 사전](카테고리-체계와-키워드.md)과 매칭. 소분류별 점수 = 매칭 키워드 수(제목 매칭은 가중치 2). 최고점 소분류 채택, 대분류는 소분류에서 유도. 제외 키워드(예: "AI 자격증 시험 감독관")가 걸리면 탈락.
2. **AI 관련성 필터**: 대부분 소스는 AI와 무관한 강좌(요가, 수채화 등)가 섞여 있다. 룰에서 아무 소분류도 안 걸리면 → AI 무관으로 보고 저장은 하되 노출 안 함(`category_main = null`).
3. **LLM 분류 (2차, 필요할 때만)**: 룰 결과가 애매한 것(점수 동률, 또는 "디지털", "스마트" 같은 약한 키워드만 걸린 것)만 모아 하루 1회 배치 호출. 출력은 카테고리 코드 목록 중 하나 + `none`으로 제한(JSON). 결과는 `category_by='llm'`으로 저장하고 다시 분류하지 않는다(제목 바뀌면 재분류).
   - 하루 신규 강좌가 수십~수백 건이라 비용은 미미하다. 소형 모델로 충분.
4. **수동 보정**: 관리자가 `category_by='manual'`로 고치면 이후 자동 분류가 덮어쓰지 않는다.
5. 정확도 점검: 월 1회 무작위 50건 샘플을 사람이 보고 키워드 사전을 고친다. 별도 평가 시스템은 만들지 않는다.

## 8. 운영 최소 장치

- 소스별 마지막 성공 시각·건수 테이블(또는 로그). 0건이거나 전일 대비 급감 시 메일/슬랙 1통.
- 크롤러: User-Agent에 서비스명·연락처, 요청 간 1~3초, robots.txt 확인, 실패 시 재시도 2회 후 포기.
- API 키는 환경변수. 고용24 키는 기업회원 명의라 담당자 변경 시 재발급 절차를 메모해 둔다.

## 9. 뺀 것과 추가 시점

- 소스 간 정교한 중복 병합 → 같은 강좌가 화면에 두 번 보인다는 피드백이 나오면
- 실시간 수집·웹훅 → 하루 1회로 마감 정보가 늦다는 불만이 나오면 (마감 임박 소스만 하루 2회로 올리는 정도)
- 별도 검색엔진(ES 등) → Postgres `ILIKE`/`pg_trgm`이 느려지면 (수만 건 이하에선 불필요)
