# 인프라 서비스 스펙 비교 (백엔드 호스팅)

- 작성 기준일 / 모든 출처 확인일: **2026-10-11**
- 원칙: 공식 페이지에서 확인한 수치만 적었다. 공식 출처로 확인하지 못한 항목은 **미확인**으로 표시했다. 2차 자료(블로그 등)에서 가져온 내용은 따로 표시했다.
- 가격은 USD 기준이며 세금(VAT) 별도.

## 0. 워크로드 전제

| 항목 | 내용 |
|---|---|
| DB | Postgres, `courses` 1만~10만 행, 500MB 미만 |
| API | 토스 미니앱용 읽기 전용 목록/검색 API. 트래픽은 낮음~중간, 사용자는 한국(서울 지연시간이 중요) |
| 배치 | 하루 1회, 약 16개 소스 수집(공개 REST API, 정적 HTML 크롤링, 그리고 1개는 headless Chromium/Playwright 필요). 실행 시간 10~30분 |
| 목표 | 최소 비용, 그리고 관리할 provider/콘솔 수 최소화 |

## 1. 서비스별 스펙

### 1.1 Supabase

| 항목 | Free | Pro |
|---|---|---|
| 가격 | $0 | "from $25/month" ($10 컴퓨트 크레딧 포함, Micro 1대 분량) |
| DB 크기 | 프로젝트당 500 MB | 프로젝트당 8 GB 디스크 포함 |
| Egress | 5 GB | 250 GB |
| 컴퓨트 | Nano: Shared CPU, 최대 0.5 GB RAM, 최대 DB 권장 500 MB | Micro: Shared, 1 GB RAM (~$10/월, 크레딧으로 상쇄) |
| 연결 수 | DB 직접 60 / Pooler 200 (Nano) | Micro도 60 / 200 |
| 활성 프로젝트 | 2개 | - |
| **일시정지** | "Free projects are paused after 1 week of inactivity." | 유료 플랜은 비활성으로 정지되지 않음 |
| 서울 리전 | **있음** (`ap-northeast-2`) | 동일 |
| Edge Functions | 50만 호출 포함. 메모리 256MB, CPU 2s/요청, wall clock **150s(Free)** / 400s(유료) | |
| pg_cron | Supabase Cron = pg_cron 기반. 권장: 동시 8개 이하, **잡당 10분 이하**. 플랜별 제공 여부는 문서에 명시 없음(미확인) | |
| 자동 REST | PostgREST로 스키마에서 REST API 자동 생성(Data API) | 동일 |
| 상업적 이용 | 공식 문구 **미확인** (2차 자료: GitHub Discussion 등에서는 허용된다고 함) | 허용(유료) |

판단: DB와 읽기 API를 한 곳에서 해결할 수 있고 서울 리전도 있다. 다만 headless 배치는 Edge Functions(150s, 256MB)나 pg_cron(10분 권장)에서 돌릴 수 없으므로 **배치 러너는 따로 있어야 한다**.

> 정정(2026-10-11): 아래 판단의 "Postgres 전제가 깨진다"는 D1을 DB로 쓸 때 이야기다. Workers에서 Supabase를 HTTP로 호출하면 Postgres를 그대로 쓸 수 있다. 그래서 Paid $5는 배치 이전 후보로 유효하다([프로젝트-구성-제안.md](프로젝트-구성-제안.md) 2-4).

판단: Free는 CPU 10ms와 브라우저 하루 10분이라 배치에 쓸 수 없다. Paid $5이면 headless까지 한 곳에서 처리할 수 있지만 Postgres 전제가 깨지고(D1=SQLite), 크롤러를 Workers 런타임(128MB, Node API 제약)에 맞게 다시 짜야 한다.

### 1.5 GitHub Actions (스케줄 워크플로)

| 항목 | 내용 |
|---|---|
| 무료 분량 | GitHub Free 기준 **private 레포 월 2,000분**. **public 레포는 표준 러너 무료** |
| 초과 단가 | Linux 2-core x64 $0.006/분 (arm64 $0.005, 1-core slim $0.002) |
| 잡 최대 시간 | 잡당 **6시간** |

| **이용약관 주의** | GitHub-hosted runner를 "any other activity unrelated to the production, testing, deployment, or publication of the software project" 용도로 쓰는 것과 "as part of a serverless application" 용도로 쓰는 것을 금지함. **운영 데이터 수집 배치를 돌리는 건 회색지대**다(직접 판단 필요) |

월 사용량 추정: 30분 × 30일 = 900분. private 레포 무료 2,000분 안에 들어간다.

## 4. 권장안

**A. Supabase(서울) + GitHub Actions**로 시작한다.
- 비용은 $0, 관리 포인트는 Supabase 콘솔 하나(GitHub은 이미 쓰는 것).
- API 서버를 따로 두지 않는다. 미니앱이 PostgREST를 직접 읽고, RLS로 `select`만 허용한다.
- 전환 트리거:
  - 출시 후 다운타임이나 백업이 신경 쓰이면 Supabase Pro $25로 올린다.
  - Actions 약관이나 cron 지연이 문제 되면 배치만 Lightsail 서울 $12로 옮긴다(= C안). 코드는 같은 스크립트를 crontab으로 돌리면 된다.
- B(Oracle)는 비용 0에 provider 1개로 숫자상 최소다. 그러나 DB 운영과 유휴 회수 위험을 직접 떠안아야 하므로 "관리 포인트 최소"와는 맞지 않는다.
