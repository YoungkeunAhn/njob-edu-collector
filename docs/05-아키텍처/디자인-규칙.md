# 디자인 규칙 — TDS + 위계 3단계

- 상위: [00-START-HERE.md](00-START-HERE.md) · 결정: [plan.md](../06-스펙/plan.md) 「결정 기록」 D19
- 2026-10-13 디자인 개선 조사에서 정한 규칙이다. **디자인 시스템을 새로 만들지 않고 토스 TDS 를 쓰고, 화면마다 위계 3단계만 지킨다.** 미니앱은 토스 앱 안에서 열리므로 토스처럼 보이는 것이 사용자에게 익숙하고 검수에도 유리하다.

## 1. 디자인 시스템: TDS 를 쓴다

### 근거
- 앱인토스는 비게임 미니앱용으로 TDS(Toss Design System)를 웹(WebView)용으로 제공한다. 패키지: `@toss/tds-mobile`(컴포넌트), `@toss/tds-mobile-ait`(Provider). [TDS 시작하기](https://tossmini-docs.toss.im/tds-mobile/start/)
- **필수는 아니다.** 공식 FAQ: "모든 컴포넌트를 TDS로 만들 필요는 없고, 가능한 한 TDS 사용을 권장한다." 커뮤니티 운영진 답변에도 "과거엔 필수였지만 지금은 아니다"라는 내용이 있다. [FAQ](https://developers-apps-in-toss.toss.im/guide/en/faq), [커뮤니티 TDS 질문](https://techchat-apps-in-toss.toss.im/t/tds/4623)
- **토스 글꼴(Toss Product Sans)은 TDS 컴포넌트를 써야만 적용된다.** 글꼴 파일은 따로 주지 않는다. (FAQ) → 지금 `index.css`의 `font-family`에 적힌 "Toss Product Sans"는 실제로 적용되지 않을 가능성이 높다.
- 우리 문서도 원래 TDS를 붙이기로 했었다: `docs/05-아키텍처/앱인토스-개발스펙.md` 160행 "Vite + React SPA에 `@apps-in-toss/web-framework`와 TDS mobile을 붙인다."
- 핵심 컴포넌트가 우리 화면 3개에 거의 1:1로 맞는다. [컴포넌트 목록](https://developers-apps-in-toss.toss.im/design/components)

| 우리 화면 요소 | TDS 컴포넌트 |
|---|---|
| 화면 제목 + 설명 | `Top` |
| 섹션 제목("지역", "분야") | `ListHeader` |
| 강좌 한 줄, 상세 항목 한 줄 | `ListRow` |
| 하단 고정 버튼 | `BottomCTA` |
| 유형·무료·마감 표시 | `Badge` |
| 유형 전환(전체/원데이/교육훈련) | `Tab` 또는 칩 버튼 |
| 안내 문구 | `Paragraph` |
| 구분선 | `Border` |

React 버전: TDS 는 `react@^18` 을 요구해 19.3 → 18.3.1 로 내렸다.

## 2. 위계 규칙: 화면마다 3단계만 쓴다

글자 크기는 TDS 타이포 토큰을 그대로 쓴다. 값을 직접 적지 말고 토큰을 써야 사용자가 큰 글씨 설정을 켰을 때 함께 커진다. [TDS Typography](https://tossmini-docs.toss.im/tds-mobile/foundation/typography/)

| 단계 | 용도 | TDS 토큰 (크기/행간) | 굵기 | 색 |
|---|---|---|---|---|
| 1 화면 주인공 | 화면 질문, 강좌 제목(상세) | Typography 2 (26/35) 또는 3 (22/31) | Bold | 진한 회색(본문색) |
| 2 판단 정보 | 강좌 제목(목록), 마감·비용 | Typography 5 (17/25.5) | Semibold | 본문색. 마감 임박·무료만 강조색 |
| 3 보조 | 기관, 지역, 기간, 안내문 | Typography 6~7 (15/22.5, 13/19.5) | Regular | 연한 회색 |

규칙은 네 줄이다.
1. **화면마다 주인공은 하나.** 홈은 질문, 목록은 강좌 제목, 상세는 강좌 제목과 "원문에서 신청" 버튼이다.
2. **파란색(강조색)은 화면당 1~2곳.** 하단 CTA와 "선택됨" 상태에만 쓴다. 지금처럼 태그 글자까지 파랗게 칠하지 않는다.
3. **간격은 4의 배수로, 섹션 사이는 넓게(24~32px), 섹션 안은 좁게(8~12px).** 같은 16px로 모두 띄우면 덩어리가 안 생긴다.
4. **주요 행동은 하단 고정 버튼 하나.** 앱인토스 비게임 체크리스트도 "CTA 버튼은 다음 행동을 예측할 수 있어야 한다"고 적는다. [비게임 출시 가이드](https://developers-apps-in-toss.toss.im/landing-page/landing-page-en/checklist/app-nongame)


## 3. 적용 기록

결정(2026-10-13): **A(TDS 채택)**. `design/tds` 브랜치에서 1~5를 한 번에 적용했다.
- React 19.3 → 18.3.1, `@toss/tds-mobile`·`@toss/tds-mobile-ait`·`@toss/tds-colors`·`@emotion/react` 추가
- 홈: 칩 선택 + `SegmentedControl`(유형) + `FixedBottomCTA`
- 목록: `Top`(조건 요약 + "조건 변경") + 유형 칩 + 카드(마감 D-day·무료 배지 → 제목 → 기관·지역 → 교육일·가격) + `Result`(빈 결과) + `Skeleton`(로딩)
- 상세: `Top`(배지·제목·기관) + `TableRow` 항목 + `FixedBottomCTA` "원문에서 신청하기"
- 라이트 모드 고정은 `TDSMobileAITProvider`가 한다(OS가 다크여도 라이트로 확인).
- 남은 것: 번들이 gzip 약 390KB로 커졌다. 시군구가 많은 시도(경기 31개)는 칩이 길다 → 필요하면 바텀시트로.
