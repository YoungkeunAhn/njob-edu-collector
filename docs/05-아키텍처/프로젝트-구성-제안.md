# 프로젝트 구성 제안

> **최종 결정은 [../06-스펙/plan.md](../06-스펙/plan.md)를 따른다.** 이 문서는 논의 과정에서 쓴 초안이다. 이후 바뀐 점: 앱이 Supabase에 직접 접근하지 않고 Cloudflare Worker 조회 API를 거친다. 수집도 GitHub Actions 대신 같은 Worker의 Cron으로 돌린다.

- 작성일: 2026-10-11
- 근거: [앱인토스-개발스펙.md](앱인토스-개발스펙.md), [인프라-서비스-스펙비교.md](인프라-서비스-스펙비교.md), [../03-데이터수집/수집-파이프라인-설계.md](../03-데이터수집/수집-파이프라인-설계.md)
- 목표: 비용은 최소로 하되, 관리할 곳이 흩어지지 않게 한다.

## 1. 한 줄 요약

**GitHub 레포 1개(모노레포) + Supabase(서울) 1개.** 앱은 앱인토스 WebView(Vite + React)로 만든다. API 서버는 따로 두지 않고, 앱이 Supabase의 자동 REST API를 읽기 전용으로 호출한다. 수집 배치는 같은 레포의 GitHub Actions가 매일 돌린다.
시작 비용은 **월 $0**이다. 관리할 콘솔은 GitHub, Supabase, 앱인토스 콘솔 3개다.

```
┌──────────────── GitHub 레포 (코드·배치·이슈 한곳) ────────────────┐
│  app/         앱인토스 미니앱 (Vite + React, .ait 번들)            │
│  collector/   수집기 (TypeScript, Playwright)                      │
│  supabase/    DB 마이그레이션, RLS 정책, 생성된 타입                │
│  .github/workflows/collect.yml   ← 매일 03:00 KST 실행             │
└──────────────────────────────────────────────────────────────────┘
        │ 빌드한 .ait 업로드              │ upsert (service_role 키)
        ▼                                 ▼
  앱인토스 (화면 파일은 토스가 서빙)   Supabase 서울 (Postgres + 자동 REST)
        │                                 ▲
        └──── 읽기 전용 조회 (anon 키 + RLS) ┘
```

## 2. 구성 요소별 결정

### 2-1. 앱: RN 대신 **WebView(Vite + React)** 권장

앱인토스는 React Native(Granite)와 WebView 두 방식을 모두 지원한다.

| 항목 | WebView (권장) | React Native (Granite) |
|---|---|---|
| 우리 화면 | 목록·필터·상세. 네이티브 성능이 필요 없다 | 같은 화면을 만들 수 있지만 이점이 없다 |
| 광고·외부 링크 API | `loadFullScreenAd`/`showFullScreenAd`, `openURL`. RN과 같다 | 같다 |
| 제약 | SSR 금지(CSR·SSG만 가능). 운영 Origin을 CORS에 허용해야 한다 | Granite 1.x로 고정되고 네이티브 모듈에 제한이 있다 |
| 개발·테스트 | 일반 브라우저에서 바로 개발할 수 있다. 나중에 웹으로도 배포할 수 있다 | 시뮬레이터나 토스앱 QR이 필요하다 |
| 코드 공유 | 수집기와 같은 TypeScript, 같은 도구 | 같다 |

RN으로 가야 한다면 `app/`만 Granite 프로젝트로 바꾸면 된다. 나머지 구성은 그대로다.

### 2-2. 백엔드 API: **별도 서버 없음**

- 앱이 Supabase REST(PostgREST)에 **anon 키**로 바로 조회한다.
- RLS로 `course` 테이블은 `select`만 허용하고, 그것도 `status = 'open'`이고 카테고리가 분류된 행만 허용한다. 쓰기는 수집기만 할 수 있다(service_role 키, GitHub Secrets에 보관).
- 화면에 필요한 조회는 PostgREST 필터로 충분하다(`sido_code=eq.11&category_main=eq.video&course_type=eq.oneday&order=apply_end`). 복잡해지면 Postgres view나 RPC 함수 1개를 추가한다.
- 앱인토스 요건 중 HTTPS와 CORS는 Supabase가 처리한다. 로그인과 mTLS는 필요 없다(토스 서버 API를 쓰지 않음).
- 광고 흐름(**확정**): 지역·카테고리를 고른 뒤 **"나에게 맞는 세미나 찾기"** 버튼을 누르면 광고가 나오고, 광고가 끝나면 목록을 보여준다. 버튼 옆에 "광고 시청 후 목록을 볼 수 있어요" 같은 툴팁을 항상 붙인다. 사용자가 직접 누르는 버튼이라 인트로·로딩 광고 금지 규정과 겹치지 않는다. 이 흐름은 앱에서 처리한다. 공개 정보라 서버에서 검증할 필요가 없다.
- 원문 링크(**확정**): 상세 화면의 보조 버튼으로 두고 SDK `openURL`로 연다.

> 별도 API 서버를 둘 시점: 사용자별 기능(찜, 알림)이 생기거나 조회 로직을 숨겨야 할 때. 그때도 Supabase Edge Function 1개로 시작한다.

### 2-3. DB: **Supabase 무료 플랜, 서울 리전**

- Postgres 1개. 스키마는 [수집-파이프라인-설계.md](../03-데이터수집/수집-파이프라인-설계.md) 3절의 `course`·`source` 테이블에 `collect_run`(실행 로그) 1개를 더한다.
- 1주일 동안 활동이 없으면 프로젝트가 멈추는 정책은 **매일 배치가 쓰기를 하므로 피할 수 있을 것으로 보인다**. 다만 "활동"의 공식 기준은 미확인이다.
- 무료 플랜에는 백업이 없다(2차 자료). `raw` 원본을 보관하고 있으므로 다시 수집하면 복구할 수 있다. 출시 후 다운타임이 걱정되면 Pro($25/월)로 올린다.
- 마이그레이션은 `supabase/migrations/*.sql`로 레포에서 관리한다. 콘솔에서 직접 고치지 않는다.

### 2-4. 수집 배치(cronjob): **GitHub Actions 스케줄**

- `.github/workflows/collect.yml`에 `schedule: cron: '0 18 * * *'`(UTC 18시 = KST 03시)와 수동 실행(`workflow_dispatch`)을 넣는다.
- ubuntu 러너에서 `npx playwright install chromium` 후 `collector`를 실행한다. 디지털배움터 같은 헤드리스 소스도 여기서 돌린다.
- 소스를 순차 실행하고, 소스 하나가 실패해도 다음 소스로 넘어간다. 소스별 건수와 성공 여부를 `collect_run`에 남긴다. 워크플로가 실패하면 GitHub이 메일로 알려준다.
- 비용: 하루 30분 × 30일 = 900분. private 레포 무료 한도 2,000분 안에 들어간다.
- **주의 2가지**
  1. GitHub Actions 약관은 "빌드·테스트·배포와 무관한 용도"를 금지한다. 데이터 수집 배치는 **회색지대**다.
  2. 부하가 몰리면 스케줄 실행이 지연될 수 있다. 하루 1회 배치라 영향은 작다.
- **문제가 생기면 옮긴다.** 수집기는 "소스별 fetch → normalize → Supabase upsert" 구조라 실행 환경에 묶이지 않는다. 옮길 후보는 아래와 같다.
  - **Cloudflare Workers Paid ($5/월)**: Cron Triggers를 쓰고, Cron 1회당 CPU 15분까지 쓸 수 있다(네트워크 대기 시간은 CPU에 포함되지 않음). Browser Rendering이 월 10시간 포함이라 디지털배움터 헤드리스 수집도 된다. DB는 Supabase를 그대로 HTTP로 호출하면 되므로 D1을 쓸 필요가 없다. Hyperdrive(Workers Free에서도 사용 가능)를 쓰면 외부 Postgres·MySQL에 드라이버로 직접 연결할 수도 있다. 다만 Cloudflare가 MySQL DB를 호스팅해 주는 것은 아니고, DB는 외부(Supabase, PlanetScale, RDS 등)에 있어야 한다. 바꿀 점은 Playwright를 `@cloudflare/playwright`로 바꾸는 것과 128MB 메모리 한도에 맞춰 소스별로 나눠 실행하는 것 정도다.
  - 그 밖에 일반 VM(Lightsail 서울 $12/월 등)의 crontab에 같은 코드를 그대로 올려도 된다.

### 2-5. 언어: **TypeScript 하나**

수집 파이프라인 설계 문서의 예시는 Python이었지만, 앱·수집기·DB 타입을 한 언어로 맞추려고 TypeScript로 통일한다.
- Playwright, `fetch`, HTML 파서(`cheerio`)로 수집에 필요한 것이 모두 해결된다.
- DB 타입은 `supabase gen types typescript`로 생성한 파일 하나를 앱과 수집기가 같이 import한다. 공용 패키지는 만들지 않는다.

## 3. 레포 구조

```
n-jobber-edu/
├─ app/                      # 앱인토스 WebView 미니앱
│  ├─ granite.config.ts
│  ├─ src/
│  │  ├─ pages/              # 홈(지역·카테고리 선택), 목록, 상세
│  │  ├─ api.ts              # supabase-js 조회 함수
│  │  └─ ads.ts              # 앱인토스 광고 호출
│  └─ package.json
├─ collector/
│  ├─ src/
│  │  ├─ main.ts             # SOURCES 배열을 순차 실행 → upsert → 마감 처리 → 분류
│  │  ├─ sources/            # 소스 1개 = 파일 1개 (fetch, normalize 두 함수)
│  │  │  ├─ work24.ts
│  │  │  ├─ lifelong-std.ts
│  │  │  ├─ digital-baeum.ts # Playwright
│  │  │  └─ ...
│  │  ├─ classify.ts         # 키워드 룰 → course_type, category 판정
│  │  └─ region.ts           # 주소 → 법정동 시군구 코드
│  └─ package.json
├─ supabase/
│  ├─ migrations/            # 테이블, 인덱스, RLS
│  └─ types.ts               # 생성된 DB 타입 (app·collector 공용)
├─ .github/workflows/
│  └─ collect.yml
├─ docs/                     # 지금의 조사·설계 문서
└─ package.json              # npm workspaces: app, collector
```

## 4. 비용과 관리 포인트

| 단계 | 구성 | 월 비용 | 관리할 곳 |
|---|---|---|---|
| 개발~출시 초기 | Supabase Free + Actions(private) | **$0** | GitHub, Supabase, 앱인토스 콘솔 |
| 안정화 (다운타임·백업이 신경 쓰일 때) | Supabase Pro | $25 | 같음 |
| Actions가 막히거나 불안정할 때 | 배치만 Cloudflare Workers Paid (Cron + Browser Rendering) | +$5 | +Cloudflare 1곳 |

광고 수익에서는 송출 운영 수수료 약 30%가 빠진다. 앱인토스 수수료 15%는 현재 프로모션으로 면제 중이다.

## 5. 탈락시킨 대안

| 대안 | 탈락 이유 |
|---|---|
| Vercel Hobby (API + Cron) | 상업적 이용 불가. 함수 최대 300초라 배치를 한 번에 못 돌린다 |
| Neon, Fly.io, Railway, Render | 서울 리전이 없어 한국 사용자 지연이 커진다 |
| Cloudflare Workers **무료 플랜** | CPU 10ms, 브라우저 하루 10분이라 배치에 못 쓴다. 유료 플랜($5)은 배치 이전 후보로 둔다(2-4) |
| Oracle Always Free VM 1대 | $0이고 관리할 곳이 1곳이지만, DB·백업·TLS·보안 패치를 직접 해야 한다. 사용량이 적으면 유휴 회수 정책에 걸릴 수 있다 |

## 6. 확정 사항과 남은 확인

**확정 (2026-10-11)**
- **서비스 성격**: 교육 콘텐츠를 파는 서비스가 아니라 **교육·세미나 정보를 알려주는 서비스**다. 앱인토스 정책의 "자격증 없는 수익형 교육 서비스" 조항은 교육 콘텐츠를 판매하는 서비스에 해당하는 것으로 보고, 우리는 정보 제공 서비스로 등록한다.
- **광고**: ~~버튼 → 전면 광고 → 목록~~ → **배너로 변경**(최종은 [../06-스펙/plan.md](../06-스펙/plan.md) D6).
- **원문 링크**: 상세 화면의 보조 버튼으로 둔다.
- **배치 환경**: GitHub Actions로 시작한다. 문제가 생기면 Cloudflare Workers 등으로 옮긴다(2-4).
