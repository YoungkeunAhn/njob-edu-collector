## 1. 조사 결과 (앱인토스 공식 문서)

### 1.1 왜 토스 로그인인가
- 로그인 소개 문서: "**기능성 푸시와 알림, 프로모션, 토스페이를 쓰려면 토스 로그인을 반드시 연동해야 해요**". [login intro](https://developers-apps-in-toss.toss.im/guide/authentication/intro.md)
- 발송 문서에는 익명 키(`x-anon-key`)로도 보낼 수 있다고 적혀 있어 서로 맞지 않는다. [smart-message (doc)](https://developers-apps-in-toss.toss.im/documentation/common/growth/smart-message.md) → 익명 키 방식은 확정할 수 없어 **토스 로그인으로 간다.**

### 1.2 토스 로그인 흐름
| 단계 | 내용 | 출처 |
|---|---|---|
| 앱 | `appLogin()` → `{ authorizationCode, referrer: 'DEFAULT' \| 'SANDBOX' }`. 처음이면 약관 동의 화면, 이미 로그인했으면 바로 코드. 토스 밖(일반 브라우저) 동작은 문서에 없음 → try/catch, 토스 밖에서는 찜 숨김 | [toss-login](https://developers-apps-in-toss.toss.im/documentation/common/authentication/toss-login.md) |
| 코드 | 10분 유효, 1회용(재사용 시 `invalid_grant`) | 위 |
| 토큰 | `POST https://apps-in-toss-api.toss.im/api-partner/v1/apps-in-toss/user/oauth2/generate-token` `{ authorizationCode, referrer }` → `accessToken`(1시간), `refreshToken`(14일), `scope`. **mTLS 필수** | 위 |
| 사용자 | `GET …/user/oauth2/login-me` (Bearer) → 평문 `userKey`(number, 앱마다 다름)·`scope`·`agreedTerms`, 고른 동의 항목만 암호화(AES-256-GCM)되어 옴. 모르는 scope 값이 와도 예외 내지 않기(2026-01-02 `user_key` 추가) | 위 |
| 연결 끊기 API | `…/access/remove-by-user-key` `{ userKey }` (readTimeout 3초, 바로 재시도 금지) | 위 |

- **개인정보는 받지 않는다.** 필요한 건 `userKey`뿐이다. `userKey`는 평문이라 복호화 키도 필요 없다(추론). 콘솔에서 동의 항목을 하나도 안 고를 수 있는지는 확인 못 함 → 안 되면 가장 가벼운 항목 하나만 고르고 그 값은 저장하지 않는다.
- **토큰은 저장하지 않는다.** `userKey`만 얻고 버린다. 푸시는 `userKey` + mTLS로 보내므로 토큰이 필요 없다(1.4). → "민감 정보 DB 암호화 저장" 체크 항목의 대상이 없다.

### 1.3 연결 해제 콜백 (출시 체크 항목)
- 콘솔에 콜백 URL·메서드·Basic Auth 값을 등록. POST면 바디 `{"userKey": 443731103, "referrer": "UNLINK" | "WITHDRAWAL_TERMS" | "WITHDRAWAL_TOSS"}`, GET이면 쿼리. Basic Auth 헤더를 등록값과 비교해 검증. 응답 규칙·재시도 정책은 문서에 없음. [toss-login](https://developers-apps-in-toss.toss.im/documentation/common/authentication/toss-login.md), [login intro](https://developers-apps-in-toss.toss.im/guide/authentication/intro.md)
- 체크리스트: "**연결을 끊으면 사용자 데이터가 미니앱에 남아 있지 않아요**", "연결을 끊은 뒤 다시 접속하면 약관 화면이 다시 나와요". → 콜백을 받으면 그 사용자의 찜을 지운다. [checklist (비게임)](https://developers-apps-in-toss.toss.im/checklist/app-nongame.md)

### 1.5 출시 검수에 걸리는 것
- 로그인 없이 주요 기능(검색·목록·상세)을 쓸 수 있어야 하고, 로그인·알림 동의창은 **관련 기능(찜)을 누른 뒤**에 띄운다. 진입하자마자 띄우면 안 된다. [exposure](https://developers-apps-in-toss.toss.im/guide/exposure.md), [checklist](https://developers-apps-in-toss.toss.im/checklist/app-nongame.md)
- 토스 로그인 외 다른 로그인 금지. 등록한 약관 URL이 정상적으로 열려야 한다.

### 1.6 약관·콘솔 (사용자 계정 작업)
- 콘솔 토스 로그인 약관 동의는 **대표관리자 계정만** 가능. [login intro](https://developers-apps-in-toss.toss.im/guide/authentication/intro.md)
- 토스 필수 약관은 자동 포함. **우리 서비스 이용약관과 개인정보 수집·이용 동의는 직접 만들어 URL로 등록**해야 한다.
- 개인정보를 해외 서버에 저장하면 국외 이전 동의문 필수. DB(Supabase)는 서울 리전. Worker(Cloudflare)는 전 세계 엣지에서 돈다 — `userKey`만 다루고 저장은 서울 DB에만 하므로 대상이 아니라고 보지만(추론) 약관 작성 때 확인.
- **mTLS 인증서**: 발급 메뉴 위치·형식·유효기간이 문서에 없다(인증서+개인 키 쌍, 만료 전 재발급, 2개 이상 등록 가능만 확인). 콘솔에서 직접 찾아야 한다. [server-api](https://developers-apps-in-toss.toss.im/documentation/integration/server-api.md). Worker에는 Cloudflare `mtls_certificates` 바인딩으로 붙인다(Cloudflare 기능, 추론).

## 2. 설계

### 2.1 흐름
```
[앱] 상세의 ☆ 찜 (토스 밖에서는 숨김)
  ├─ 세션 토큰이 없으면 appLogin() → POST /me/login {authorizationCode, referrer}
  │     Worker: generate-token(mTLS) → login-me → userKey
  │             app_user upsert → 세션 토큰(HMAC 서명, userKey 포함) 반환. 토스 토큰은 버린다
  │     앱: 세션 토큰을 Storage 에 저장
  ├─ 처음 찜할 때 requestNotificationAgreement (거절해도 찜은 된다)
  └─ PUT·DELETE /me/bookmarks/:courseId, GET /me/bookmarks  (Authorization: Bearer 세션 토큰)
[토스 → Worker] POST /toss/unlink (Basic Auth) → app_user 삭제(찜 cascade 삭제)
[Worker cron] 매일 10:00 KST → 내일 마감인 찜 중 안 보낸 것 → send-message(mTLS, x-toss-user-key) → notified_at
```
- 세션 검증 때 `app_user` 행이 있는지 본다 → 연결을 끊으면 행이 없어 401 → 앱이 다시 `appLogin` → 약관 화면이 다시 뜬다(체크 항목 충족).

### 2.2 DB (마이그레이션 1개)
```sql
create table app_user (
  user_key   bigint primary key,           -- 토스 login-me userKey. 개인정보 컬럼 없음
  created_at timestamptz not null default now()
);
create table bookmark (
  user_key    bigint not null references app_user (user_key) on delete cascade,
  course_id   bigint not null references course (id) on delete cascade,
  created_at  timestamptz not null default now(),
  notified_at timestamptz,                 -- 마감 알림 보낸 시각(한 번만)
  primary key (user_key, course_id)
);
```
- 강의가 마감·원천 삭제로 지워지면 찜도 지워진다(알림은 그 전 날에 나간다). `course.id`는 upsert(`source, source_id`)로 유지된다.
- 앱은 DB에 직접 붙지 않는다(plan D3 유지). RLS 켜고 anon 권한 없음.

### 2.3 Worker 변경
- 새 경로(캐시 안 함): `POST /me/login`, `GET /me/bookmarks`, `PUT·DELETE /me/bookmarks/:courseId`, `POST /toss/unlink`.
- CORS: 지금 `GET, OPTIONS`만 → `/me/*`에 `POST, PUT, DELETE`와 `authorization` 헤더 허용. `/toss/unlink`는 CORS 없음.
- 새 Cron: `0 1 * * *`(UTC 01:00 = KST 10:00) 마감 알림. 결과 요약은 텔레그램으로.
- 새 시크릿·바인딩: mTLS 인증서(`mtls_certificates`), `SESSION_SECRET`, `TOSS_UNLINK_BASIC_AUTH`, `PUSH_TEMPLATE_CODE`.

### 2.4 앱 변경
- SDK `@apps-in-toss/web-framework` 3.5.0 → 최신(로그인·동의 함수 확인 후 버전 고정).
- 상세 화면 찜 버튼, 목록 카드 찜 표시, 홈 위쪽 "찜한 강의 N" → 찜 목록 화면(1개 추가).

### 2.5 푸시 문구(초안, 검수 대상)
- 제목(7자 이내): **마감 임박**
- 본문(25자 이내): **찜한 {강의} 접수가 내일 마감돼요.** — "신청하세요" 같은 유도 문구 없음
- 이동: 해당 강의 상세 화면
