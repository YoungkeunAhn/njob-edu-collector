# 앱인토스(Apps in Toss) 개발 스펙 조사

- 확인일: 2026-10-11 (아래 사실은 모두 이 날짜에 확인)
- 대상 서비스: N잡러 교육 매칭. AI 강의를 지역·카테고리로 목록/검색하고, 광고 시청 후 목록을 보여 준다. 데이터는 자체 백엔드 DB(매일 크롤링)에서 가져온다.
- 표기: **미확인**은 공식 문서에서 찾지 못한 내용이다. **추론**은 문서 사실로부터 도출했지만 문서에 직접 적혀 있지는 않은 내용이다.
- 문서 인덱스: https://developers-apps-in-toss.toss.im/llms.txt

## 1. 개발 방식

### 1.1 지원 방식
| 방식 | SDK 패키지 | 최신 버전 (npm, 2026-10-11) | 출처 |
|---|---|---|---|
| WebView (웹 프레임워크) | `@apps-in-toss/web-framework` | `3.8.0` (2026-10-08 배포) | https://developers-apps-in-toss.toss.im/ai-vibe-coding/tutorials/webview.md , https://registry.npmjs.org/@apps-in-toss/web-framework |
| React Native (Granite) | `@apps-in-toss/framework` + `@granite-js/react-native` | framework `2.10.13`, granite `1.0.45` (latest 태그) | https://developers-apps-in-toss.toss.im/ai-vibe-coding/tutorials/react-native.md , https://registry.npmjs.org/@apps-in-toss/framework |

- Granite는 토스가 만든 React Native 프레임워크다(github.com/toss/granite, Apache 2.0). 문서는 **Granite 1.x만 사용**하라고 하며, 다른 버전은 앱인토스 개발 환경과 호환되지 않는다고 적고 있다. npm에는 `stable-v2`, `stable-v3` 태그도 있지만 문서 기준은 1.x다. (출처: react-native.md, https://github.com/toss/granite)
- RN 버전: `@apps-in-toss/framework`의 peerDependency가 `react-native: *`라서 정확한 RN 버전은 **미확인**이다.
- WebView 쪽 웹 프레임워크 제한: 문서에 지원 프레임워크 목록은 없다. 예제는 Vite + React(TDS를 쓸 경우 `react@^18`)다. (webview.md)
- 렌더링 제약: **SSR은 쓸 수 없고 CSR 또는 SSG만 가능하다.** `eval` 같은 외부 코드 실행도 금지다. (https://developers-apps-in-toss.toss.im/checklist/app-nongame.md)
  → Next.js는 SSR 없이 `output: 'export'` 정적 빌드로만 쓸 수 있다(추론).

### 1.2 스캐폴드 / CLI
**WebView**: 기존 웹 프로젝트에 SDK를 붙인다.
```
npm i @apps-in-toss/web-framework
npx ait init          # framework 선택, appName 입력
npm run dev           # granite.config.ts의 web.commands.dev 실행 (예: vite --host)
npm run build         # .ait 번들 생성
```
- `granite.config.ts` 필드: `appName`(콘솔 등록명과 같아야 함, `intoss://{appName}`), `brand{displayName, primaryColor, icon}`, `web{host, port, commands{dev, build}}`, `permissions`, `outdir: 'dist'`. (webview.md)
- UI(선택): `@toss/tds-mobile`, `@toss/tds-mobile-ait` (webview.md)

**React Native**
```
npm create granite-app@"^1"
npm i @apps-in-toss/framework
npx ait init
npm i @toss/tds-react-native
npm run dev   # Metro (8081, 5173 포트)
npm run build # 프로젝트 루트에 <서비스명>.ait 생성
```
(react-native.md) 네이티브 모듈이 필요한 라이브러리는 앱인토스가 지원하는 범위 안에서만 쓸 수 있다.

### 1.3 빌드 → 배포 → 심사 흐름
1. `npm run build`로 `.ait` 번들 생성
2. 업로드: 콘솔에서 올리거나 CLI로 `npx ait token add` 후 `npx ait deploy` 실행(`-m` 메모, `--timeout` 10~300초 지정 가능). CI/CD 업로드는 SDK v1.4.0 이상에서 된다. (https://developers-apps-in-toss.toss.im/guide/operation/toss.md)
3. 테스트: `intoss-private://appsintoss?_deploymentId=...` QR로 실제 토스앱에서 확인한다. **테스트를 1회 이상 완료해야 검토를 요청할 수 있다.** (toss.md, https://developers-apps-in-toss.toss.im/guide/operation/console-workspace.md)
4. 검토 요청 → 승인 → '출시' 버튼. 출시하면 사용자에게 즉시 반영된다. 이전 버전을 골라 다시 출시하는 방식으로 롤백한다. (https://developers-apps-in-toss.toss.im/guide/operation/deploy.md)
5. 검토 기간은 **영업일 3~7일**이다. (console-workspace.md)
6. 2026-10-01부터는 첫 등록 때 앱 정보와 번들 검수를 한 번에 요청할 수 있다. 첫 승인 이후에는 다시 따로 요청한다. (https://toss.im/apps-in-toss/blog/update-26-10-07)
- 번들 크기: **압축 해제 기준 100MB 이하** (console-workspace.md)
- 로컬 개발은 샌드박스앱으로 한다. 샌드박스에서는 광고와 사용자 키가 동작하지 않거나 mock 데이터를 돌려준다(3장, 2.3 참고).

### 1.4 모노레포
- 공식 문서에서 모노레포 관련 언급은 찾지 못했다(**미확인**). `granite.config.ts`가 프로젝트 루트 기준이고, `npx ait`/`pnpm ait`/`yarn ait`를 모두 지원하므로 pnpm workspace의 한 패키지로 두는 구성은 가능해 보인다(추론, 검증 필요). RN은 Metro와 심볼릭 링크 이슈가 생길 수 있어 WebView 쪽이 더 안전하다(추론).

## 2. 백엔드 연동

### 2.1 자체 API 호출
- **운영 토스앱은 HTTPS만 허용한다.** HTTP는 차단된다(샌드박스는 HTTP 허용). (toss.md) 체크리스트에도 API는 HTTPS, WebSocket은 `wss://`를 쓰라고 되어 있다. (app-nongame.md)
- **WebView CORS**: 자체 서버의 CORS 허용 목록에 미니앱 Origin을 추가해야 한다. (toss.md)

| SDK 버전(번들) | 운영 Origin | QR 테스트 Origin |
|---|---|---|
| 3.1.1 이상 | `https://<appName>.apps.tossmini.com` | `https://<appName>.private-apps.tossmini.com` |
| 3.0.0 ~ 3.1.1 미만 | `https://<appName>.web.tossmini.com` | `https://<appName>.private-web.tossmini.com` |
| 1.x ~ 2.x | `https://<appName>.apps.tossmini.com` | `https://<appName>.private-apps.tossmini.com` |

- iOS 13.4 이상에서는 서드파티 쿠키가 전부 차단된다. 쿠키 대신 토큰 기반 인증을 써야 한다. (toss.md)
- 토스가 관리하는 도메인 허용목록(우리 API 도메인을 콘솔에 등록하는 방식) 같은 요건은 **미확인**이다. 문서에서는 찾지 못했다.
- RN은 표준 `fetch`/`XMLHttpRequest`를 지원한다. (https://developers-apps-in-toss.toss.im/documentation/common/network-environment/network.md)

### 2.2 토스 서버 API와 mTLS
- 토스 서버 API(로그인 토큰, 결제 등)는 **전부 mTLS 클라이언트 인증서로 호출 주체를 식별한다.** (https://developers-apps-in-toss.toss.im/api/auth.md)
- 미니앱에서 **자체 백엔드**를 호출할 때는 mTLS가 필요 없다. 문서상 mTLS는 토스 API 호출에만 걸리는 요건이다(auth.md 범위로 판단, 추론).
- 우리 서비스는 토스 서버 API를 쓸 일이 없으므로 mTLS 인증서도 필요 없다.

### 2.3 로그인과 사용자 키
- 로그인은 필수가 아니다. 다만 **로그인을 제공한다면 토스 로그인만 쓸 수 있다.** 기능성 푸시, 프로모션(토스포인트), 토스페이를 쓰려면 토스 로그인이 필요하다. (https://developers-apps-in-toss.toss.im/guide/authentication/intro.md , https://developers-apps-in-toss.toss.im/intro/guide.md)
- 토스 로그인은 SDK 인가코드 → 서버에서 AccessToken 발급(mTLS) → 사용자정보 복호화 순서로 진행된다. 연결 해제 콜백 엔드포인트와 복호화 키 보관도 필요해서 구현 부담이 크다. (intro.md)
- **사용자 식별키** `User.getAnonymousKey`(비게임): 로그인·동의 화면 없이 미니앱별 고유 키를 받는다. 재설치하거나 기기를 바꿔도 같은 키이고, 개인정보는 포함하지 않는다. 토스 서버 API 호출용이 아니다. 샌드박스에서는 mock 값을 돌려준다. (https://developers-apps-in-toss.toss.im/guide/authentication/anon-key.md)
- 결론: 목록 앱에는 **로그인이 필요 없다.** 즐겨찾기 같은 사용자별 데이터가 생기면 anonymousKey로 충분하다.

## 3. 광고 (인앱 광고 2.0)

- 미니앱 안에서는 **앱인토스 전면형·보상형·배너 광고만 허용된다.** 외부 광고 네트워크(애드센스, 직접 붙인 AdMob 등)는 금지다. (intro/guide.md)
- API는 RN과 WebView가 같다: `loadFullScreenAd` → `loaded` 이벤트 → `showFullScreenAd`. 전면형과 보상형은 adGroupId로 구분한다. 패키지는 Web이 `@apps-in-toss/web-framework`, RN이 `@apps-in-toss/framework`다. (https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/interstitial-rewarded-ad.md)
- 이벤트: `requested`, `show`, `impression`(수익 발생 시점), `clicked`, `dismissed`, `failedToShow`, `userEarnedReward`. **보상은 `userEarnedReward`에서만 지급하고 `dismissed`에서는 지급하지 않는다.** (interstitial-rewarded-ad.md)
- 화면에 진입할 때 미리 로드하고, load → show → load 순서를 지킨다. adGroupId당 미리 로드할 수 있는 광고는 1개다. 로드 시간은 Toss Ads가 보통 1~2초(최대 약 10초), AdMob이 5~20초(최대 60초)다. (interstitial-rewarded-ad.md)
- 최소 토스앱 버전은 5.247.0(ver2)이다. iOS에서 ATT를 허용하지 않으면 로드에 실패할 수 있다. **샌드박스는 광고를 지원하지 않으므로 QR로 테스트한다.** 테스트 ID: `ait-ad-test-interstitial-id`, `ait-ad-test-rewarded-id`, `ait-ad-test-banner-id`. 테스트에 실제 ID를 쓰면 제재 대상이다. (interstitial-rewarded-ad.md)
- 배너는 Web과 RN 문서가 따로 있다: https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/web-banner.md , https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/rn-banner.md
- 사전 요건: **사업자 정보 등록 → 정산정보 검토(영업일 2~3일) → 콘솔에서 광고 그룹 생성**(Google 등록까지 최대 2시간). 광고 정책은 Google AdMob 정책을 따른다. (https://developers-apps-in-toss.toss.im/guide/monetization/in-app-ad.md)
- 배치 정책: 인트로·로딩·팝업 모달 같은 일시적인 화면에는 광고를 노출할 수 없다. 배너는 스크롤되는 화면에만 둔다. 클릭을 유도하는 것과 막다른 화면, 뒤로가기 차단은 금지다. (app-nongame.md, in-app-ad.md)
- **"광고 시청 후 목록 열람" 게이트**: 문서에 콘텐츠를 광고 뒤에 잠그는 것에 대한 명시 규정은 없다(**미확인**). 보상형 광고로 사용자가 직접 고르게 하고 `userEarnedReward` 이후에 열어 주는 방식이 정책에 가장 잘 맞는다(추론). 앱에 들어오자마자 강제로 전면 광고를 띄우는 방식은 '인트로/로딩 화면 광고 금지'와 '진입 시 강제 바텀시트 금지'에 걸릴 위험이 크다.
- 수익: 예상 수익 = 노출 수 × eCPM ÷ 1000. 매월 1일에 확정되고 그달 말에 입금된다. (in-app-ad.md)

## 4. 비용

- 입점, 워크스페이스, 출시 비용: 문서에 언급이 없다(**미확인**, 무료로 보이나 확인 필요). (console-workspace.md)
- 광고 수익 분배 (https://developers-apps-in-toss.toss.im/guide/settlement.md):
  - 광고 송출 운영 수수료: 광고수익의 약 30%. 외부 미디에이션은 플랫폼 수수료를 뗀 뒤, Toss Ads는 VAT 포함 금액에서 뗀다.
  - 앱인토스 수수료: 광고수익의 15%. **현재 프로모션으로 면제 중**이며, 사전 고지 후 바뀔 수 있다.
- 인앱결제 수수료(우리는 해당 없음): 마켓 15~30%, 토스 5%(CBT 기간에는 0%). (settlement.md)
- 정산은 사업자 단위로 한다. 일반과세자는 팝빌 역발행 세금계산서를 승인해야 하고, 간이과세자는 현금영수증을 발행한다. 5,000원 이하는 이월된다. (settlement.md)
- **호스팅**: 토스가 정적 번들을 호스팅한다는 명시 문구는 **미확인**이다. 다만 `.ait` 번들을 콘솔에 업로드하고, 운영 Origin이 `https://<appName>.apps.tossmini.com`이며, "최종 노출 콘텐츠는 토스 도메인 안에서 렌더링되어야 한다"는 규정이 있으므로 **프론트 정적 파일은 토스 쪽에서 서빙되고, 우리는 API 백엔드만 따로 호스팅하면 된다**고 볼 수 있다(추론). (toss.md, app-nongame.md)
- 제한: 번들은 압축 해제 기준 100MB 이하다. 그 밖의 트래픽·요청 한도는 **미확인**이다.

## 5. 심사·정책 제약 (우리 서비스 관련)

### 5.1 외부 링크 이동 (원 강의 사이트로 이동) — 가장 중요
- 정의: "사용자를 토스 미니앱 환경 밖의 웹·앱으로 보내는 행위". (https://developers-apps-in-toss.toss.im/intro/guide.md §2-2)
- 허용될 수 있는 경우에 **"단순 정보 확인을 위한 타사 웹사이트 이동"**, "공공기관·제휴기관 공식 페이지 연결", "각 제품을 소개·추천한 뒤 최저가 구매 플랫폼으로 이동"이 포함된다. (intro/guide.md)
- 제한되는 경우: 외부 결제창 이동, 앱 설치 페이지, **"주요 기능이 외부 링크에 의존하는 구조"**, 자사 사이트 홍보. 콘솔에 설정한 '앱 내 기능'은 미니앱 안에서 완결되어야 한다. (intro/guide.md)
- 구현 제약: 외부 사이트를 `window.location` 이동이나 iframe/중첩 WebView로 띄우는 것은 금지다. 외부 링크는 SDK `openURL(url)`로 기기 기본 브라우저에서 연다(Web은 `@apps-in-toss/web-framework`, RN은 `@granite-js/react-native`). (app-nongame.md, https://developers-apps-in-toss.toss.im/documentation/common/screen/open-url.md)
- **설계 시사점(추론)**: 검색, 필터, 강의 상세(일정, 비용, 지역, 요약)는 미니앱 안에서 끝나야 한다. '원문 보기/신청하기'는 상세 화면 하단의 보조 링크로만 두고 `openURL`로 연다. 목록에서 바로 외부로 나가는 구조는 반려될 위험이 있다. 공공기관 강의(예: 고용24, 지자체)는 "공공기관 공식 페이지 연결"에 해당하므로 유리하다.

### 5.2 크롤링 데이터 표시
- 앱인토스 정책 문서에 크롤링이나 타사 콘텐츠 표시에 대한 규정은 없다(**미확인**). 저작권과 원 사이트 약관 문제는 우리가 따로 검토해야 한다.

### 5.3 카테고리: 교육
- 교육 서비스는 "확인이 필요한 카테고리"다: **"국가 전문 자격증이나 국가 기술 자격증이 없는 상태에서 수익이 발생하는 서비스는 출시할 수 없어요."** (intro/guide.md)
- 우리는 강의 정보 목록·중개 앱이고, 수익원은 광고다. 이 조항이 '교육 제공자'에게만 적용되는지, 광고 수익이 있는 정보 서비스에도 적용되는지는 **미확인**이다. 카테고리를 '교육'이 아닌 정보·생활 쪽으로 분류할 수 있는지도 포함해 **콘솔 채널톡으로 사전 문의가 필요하다(최대 리스크).**
- 기존 서비스를 단순히 홍보하려는 목적의 출시는 금지다. (intro/guide.md)

### 5.4 기타 체크리스트 (비게임)
- 앱인토스 내비게이션 바를 쓴다. 첫 화면에서 뒤로가기를 누르면 미니앱이 종료되어야 한다. 라이트 테마만 쓰고 핀치줌은 막는다. 인터랙션이 2초 넘게 지연되면 안 된다. 진입 시 강제 바텀시트는 금지다. (app-nongame.md)
- 2026-10-22부터 노출 정책이 출시 → 추천 → 부스팅 3단계로 바뀐다. 추천 선정에는 UX와 지표가 반영되므로 콘솔에 전환 지표를 등록해야 한다. (https://toss.im/apps-in-toss/blog/update-26-10-07)
- 등록 연령은 현재 19세 이상만 가능하다. 앱 로고는 600×600 PNG다. 비게임 앱은 '주요 기능'을 `intoss://` 링크로 등록한다. (console-workspace.md)

## 6. 권장안: WebView (Vite + React, CSR)

| 기준 | WebView | React Native (Granite) |
|---|---|---|
| 우리 요구(목록, 필터, 상세, 광고, openURL) | 모두 지원 | 모두 지원 |
| 광고 API | 같음 (`loadFullScreenAd`/`showFullScreenAd`) | 같음 |
| 백엔드 호출 | fetch + **CORS에 Origin 2개 등록 필요** | fetch, CORS 불필요(추론) |
| 개발·디버깅 | 브라우저, Vite, 웹 디버그 툴즈 | Metro, adb reverse, 샌드박스 필수 |
| 버전 제약 | SDK 3.x가 활발함(3.8.0) | Granite **1.x 고정**, RN 버전 미확인, 네이티브 모듈 제한 |
| 이식성 | 같은 코드를 일반 웹으로도 배포 가능(추론) | 앱인토스 전용 |

**WebView를 권장하는 이유**
1. 화면이 목록, 필터, 상세뿐이라 네이티브 성능이 필요 없다.
2. 광고와 openURL API가 RN과 같아서 RN을 써서 얻는 기능상 이득이 없다.
3. Granite 1.x 고정, 네이티브 모듈 제한, Metro·adb 설정 같은 RN 쪽 제약을 피할 수 있다.
4. 크롤링 백엔드와 언어(TS)·타입을 공유하기 쉽고, 나중에 일반 웹으로 확장할 수 있다.

**구조 시사점**
- `app/`: Vite + React SPA(CSR, SSR 금지)에 `@apps-in-toss/web-framework`와 TDS mobile을 붙인다. `granite.config.ts`의 `outdir: dist`.
- `api/`: 자체 HTTPS API. CORS에 `https://<appName>.apps.tossmini.com`과 `https://<appName>.private-apps.tossmini.com`을 허용한다. 쿠키 없이 쓴다.
- `crawler/`: 매일 배치로 돌려 DB를 채운다.
- 로그인, mTLS, 토스 서버 API는 쓰지 않는다. 사용자별 기능이 필요해지면 `getAnonymousKey`를 쓴다.

## 미확인 / 사전 문의 목록
1. 교육 카테고리의 자격증 조건이 광고 수익형 강의 '정보' 앱에도 적용되는지 (최대 리스크)
2. 앱에 들어오자마자 광고를 봐야 목록을 볼 수 있는 게이트가 정책상 허용되는지
3. 크롤링 콘텐츠 표시에 관한 정책
4. 입점·호스팅 비용이 없는지, 정적 번들 호스팅 주체를 명시한 문구
5. 모노레포 공식 지원 여부, Granite 1.x가 쓰는 RN 버전
